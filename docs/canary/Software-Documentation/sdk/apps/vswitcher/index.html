Video Switcher Application

A GStreamer-based application that allows runtime switching between two video sources with a single display output.

Overview​

This application creates a GStreamer pipeline with an input-selector element that enables seamless switching between two video sources (USB cameras or test patterns) during runtime. Both sources run continuously, and switching between them is instantaneous without pipeline teardown.

Features​

  • Dual Source Support: Switch between two video sources in real-time
  • Flexible Input: Supports USB cameras (/dev/videoX) and GStreamer test patterns (test0, test1, etc.)
  • Mixed Resolution Support: Handles sources with different resolutions (e.g., 1280x720 and 640x480)
  • Mixed Format Support: Handles sources with different pixel formats (e.g., I420, BGRA, YUYV)
  • Input-Selector Architecture: Both sources run continuously; switching is instant via pad selection
  • Wayland Display: Fullscreen output using waylandsink with automatic scaling
  • CPU Optimized: Minimal pipeline elements for maximum efficiency
  • User-Friendly: Simple keyboard controls ('1', '2', 'q')
  • Yocto SDK Compatible: Cross-compilation ready

Architecture​

Optimized Pipeline Design​

The application uses a CPU-optimized pipeline with minimal elements:

┌─────────────────────────────────────────────────────────────────┐
│                  Video Switcher Pipeline                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                               Source 1 (v4l2src/videotestsrc)   │
│                               Any resolution/format     │       │
│                                                         │       │
│                                                         │       │
│                                                         │       │
│  Source 2 (v4l2src/videotestsrc)                        │       │
│      │  Any resolution/format                           │       │
│      │                                                  │       │
│      └──────────────> input-selector <──────────────────┘       │
│                            │                                    │
│                            │  Active source passes through      │
│                            ▼                                    │
│                       videoconvert ──────> waylandsink          │
│                  (format conversion)    (auto-scale fullscreen) │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Building​

Native Build​

make

Cross-Compilation with Yocto SDK​

source /path/to/environment-setup-<arch>
make

The Makefile is Yocto SDK compatible and will automatically use the SDK toolchain when sourced.

Usage​

Basic Usage​

./vswitch [source1] [source2]

Examples​

Two USB Cameras:

./vswitch /dev/video0 /dev/video2

Two Test Patterns:

./vswitch test0 test1

Mixed (USB Camera + Test Pattern):

./vswitch /dev/video3 test0

Test Pattern Options​

Test patterns are specified as testN where N is the pattern number:

  • test0: SMPTE color bars
  • test1: Snow (random)
  • test2: Black
  • test3: White
  • test4: Red
  • test5: Green
  • test6: Blue
  • ... (additional patterns available in videotestsrc)

Controls​

While the application is running:

  • 1: Switch to Source 1
  • 2: Switch to Source 2
  • q or Q: Quit application

Configuration​

The application automatically scales all input to fullscreen using waylandsink. No manual resolution configuration is needed.

Handling Different Input Resolutions​

The pipeline automatically handles sources with different resolutions and pixel formats:

Example: Mixed resolutions

  • Source 1: 1280x720 @ I420 format
  • Source 2: 640x480 @ BGRA format
  • Output: Automatically scaled to display's native resolution in fullscreen

The single videoconvert element after the input-selector dynamically handles all format conversions.

Technical Details​

Pipeline Elements​

  • v4l2src: Video4Linux2 source for USB cameras
  • videotestsrc: Generate test patterns
  • input-selector: Select active input pad (the core switching element)
  • videoconvert: Format conversion (single instance handles all sources)
  • waylandsink: Display output on Wayland compositor with automatic scaling

Switching Mechanism​

The application uses GStreamer's input-selector element for switching:

  1. Both video sources run continuously in the pipeline
  2. Each source connects directly to a different sink pad of the input-selector
  3. Switching changes the active-pad property of the selector
  4. The single videoconvert after the selector dynamically adapts to the active source's format

Dependencies​

  • GStreamer 1.0
  • GStreamer plugins:
    • gst-plugins-base (videoconvert, videotestsrc)
    • gst-plugins-good (v4l2src)
    • gst-plugins-bad (waylandsink, input-selector)
  • pthread library

Troubleshooting​

Wayland display issues​

If the test is being run on Sentinel platform, then you will have to issue the following commands.

  • Ensure XDG_RUNTIME_DIR and WAYLAND_DISPLAY are set: 
    export XDG_RUNTIME_DIR=/var/run/user/0
    export WAYLAND_DISPLAY=wayland-1

Implementations​

This application provides two implementations:

  1. vswitch - Element-based pipeline construction

    • Source: vswitch.cpp
    • Creates GStreamer elements programmatically using gst_element_factory_make()
    • Full control over element properties and pad connections

  2. vswitch_string - String-based pipeline construction

    • Source: vswitch_string.cpp
    • Uses gst_parse_launch() to create pipeline from string description
    • Retrieves elements by name using gst_bin_get_by_name()
    • More concise pipeline definition

Both implementations provide identical functionality and switching behavior.
