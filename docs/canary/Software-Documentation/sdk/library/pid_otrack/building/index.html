Building from Source

This page describes how to build the PID Object Tracker library from source using the Meson build system.

Prerequisites​

Before building, ensure you have the following dependencies installed:

  • Meson build system (>= 0.54)
  • Ninja build tool
  • C++17 compatible compiler (g++ or clang++)
  • libmosquitto (MQTT client library) - required if building with MQTT
  • libcjson (JSON parsing) - required if building with MQTT
  • PTZ control library - required if building with PTZ support

Installing Dependencies​

On Debian/Ubuntu systems:

sudo apt-get update
sudo apt-get install meson ninja-build g++ libmosquitto-dev libcjson-dev
Yocto SDK Toolchain Setup

For standalone SDK builds using the Yocto toolchain, you must first create and source the SDK environment before building. See the Toolchain Setup documentation for instructions on creating and installing the SDK toolchain.

# Source the SDK environment
source /path/to/sdk/environment-setup-<arch>-poky-linux

# Then proceed with building
cd sentinal_sdk/image/pid_otrack
meson setup build
meson compile -C build

Build Options​

The library supports the following build-time configuration options:

OptionValuesDefaultDescription
commmqtt, nonemqttCommunication framework for receiving detections
ptzenabled, disableddisabledPTZ hardware control support

Building with Default Configuration​

1. Configure Build​

cd sentinal_sdk/image/pid_otrack
meson setup build

2. Build Library​

meson compile -C build

3. Install Library​

meson install -C build

This installs:

  • Shared library: libpid_otrack.so → $PREFIX/lib/
  • Header files: *.h → $PREFIX/include/pid-otrack/

Build Configuration Examples​

Build with MQTT Communication (Default)​

meson setup build -Dcomm=mqtt
meson compile -C build

This enables:

  • MQTT client for receiving object detections
  • JSON parsing for detection messages
  • Preprocessor define: -DCOMM_MQTT

Build without Communication Layer​

meson setup build -Dcomm=none
meson compile -C build

This creates a standalone library for manual detection updates.

  • Preprocessor define: -DDISABLE_MQTT

Build with PTZ Control Support​

meson setup build -Dcomm=mqtt -Dptz=enabled
meson compile -C build

This enables hardware PTZ control integration.

  • Preprocessor define: -DPTZ_ENABLED
  • Links with: libptctrl.a
PTZ TCP Server Required

When building with -Dptz=enabled, you must run the PTZ TCP server (test/ptz_tcp_server.py) before running the test application, otherwise it will fail at initialization. See PTZ TCP Server Setup section below for details.

Custom Build Configuration​

meson setup build \
    -Dcomm=mqtt \
    -Dptz=enabled \
    -Dbuildtype=release \
    -Dprefix=/usr/local
meson compile -C build
meson install -C build

Build Types​

Configure build type using -Dbuildtype:

Build TypeOptimizationDebug InfoUse Case
debug-O0FullDevelopment
debugoptimized-O2 -gYesTesting (default)
release-O3MinimalProduction
minsize-OsNoEmbedded systems

Reconfigure Build​

To change build options after initial setup:

meson configure build -Dcomm=none -Dptz=disabled
meson compile -C build

Clean Build​

rm -rf build
meson setup build
meson compile -C build

Test Application​

The library includes a test application (test_pid_otrack) for validating functionality.

Building Test Application​

The test application is automatically built with the library:

meson compile -C build

Test executable location: build/test_pid_otrack

Running Test Application​

./build/test_pid_otrack

The test application demonstrates:

  • Library initialization
  • Detection updates
  • PID control calculations
  • Mode switching
  • Target selection

PTZ TCP Server Setup​

Required for PTZ-Enabled Builds

If you built the library with -Dptz=enabled, the test application will fail unless the PTZ TCP server is running.

Why is this needed?​

The test application initializes PTZ control at startup. If built with PTZ enabled, it calls pt_init() which attempts to connect to the PTZ TCP server. If the server is not running, initialization will fail:

[ERROR] Failed to initialize PTZ control
        Make sure the PTZ TCP server is running!

Starting the PTZ TCP Server​

The library includes a Python-based PTZ TCP server simulator for testing purposes.

Location: test/ptz_tcp_server.py

Usage:

# Make the script executable
chmod +x sentinal_sdk/image/pid_otrack/test/ptz_tcp_server.py

# Start server on all interfaces (default port 5005)
./sentinal_sdk/image/pid_otrack/test/ptz_tcp_server.py

# Or specify custom host and port
./sentinal_sdk/image/pid_otrack/test/ptz_tcp_server.py --host 169.254.11.105 --port 5005

# Or start on localhost only
./sentinal_sdk/image/pid_otrack/test/ptz_tcp_server.py --host 127.0.0.1

Server Options:

  • --host HOST: Host address to bind to (default: 0.0.0.0 - all interfaces)
  • --port PORT: Port to listen on (default: 5005)
  • -h, --help: Show help message

Running Test with PTZ Server​

Open two terminal windows:

Terminal 1 - Start PTZ Server:

cd sentinal_sdk/image/pid_otrack
./test/ptz_tcp_server.py --host 169.254.11.105 --port 5005

Terminal 2 - Run Test Application:

cd build
./test_pid_otrack

Alternative: Build Without PTZ​

If you don't need PTZ control or don't want to run the TCP server, rebuild without PTZ support:

# Reconfigure existing build
meson configure build -Dptz=disabled
meson compile -C build

# Or clean build
rm -rf build
meson setup build -Dcomm=mqtt -Dptz=disabled
meson compile -C build

Cross-Compilation​

For cross-compilation with Yocto SDK:

source /path/to/yocto/sdk/environment-setup-script

meson setup build --cross-file=cross-compile.ini
meson compile -C build

Troubleshooting​

Build Issues​

Error: dependency 'libmosquitto' not found

  • Install MQTT library: sudo apt-get install libmosquitto-dev
  • Or build without MQTT: meson setup build -Dcomm=none

Error: dependency 'libcjson' not found

  • Install cJSON: sudo apt-get install libcjson-dev
  • Or build without MQTT: meson setup build -Dcomm=none

Error: PTZ library not found

  • Ensure lib/ptz/libptctrl.a exists
  • Or build without PTZ: meson setup build -Dptz=disabled

Runtime Issues​

Test application fails with "Failed to initialize PTZ control"

  • Cause: Built with PTZ enabled but PTZ TCP server is not running
  • Solution 1: Start the PTZ TCP server before running the test (see above)
  • Solution 2: Rebuild without PTZ support
