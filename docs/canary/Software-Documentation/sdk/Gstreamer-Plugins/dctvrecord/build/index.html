Build and Test

For building the Gstreamer plugins, we provide a meson build system. They are:

  1. Gstreamer plugin.
  2. Plugin API library.
  3. Test applications.
note

Make sure that the toolchain is setup, if you are building for the Sentinel platform.

Build with Meson​

Basic Build (With MQTT Support)​

The dctvrecord plugin requires MQTT support to function properly for AUTO mode:

# Remove any build directory if already present:
rm -rf builddir/

# Setup build directory with MQTT support
meson setup builddir

# Compile
meson compile -C builddir

Once the compilation is done, the following files among other should be generated in the builddir.

builddir/                   # Build directory
├── libapidctvrecord.a      # Plugin API library
├── libgstdctvrecord.so     # GStreamer plugin
├── selftest                # Comprehensive automated test suite
├── test_api_dctvrecord     # Interactive API test application (uses API wrapper)
├── test_gst_dctvrecord     # Interactive GStreamer test application (uses g_object_set/get)
└── mqtt_publisher          # MQTT publisher utility for AUTO mode testing

Running the examples​

The examples can be run in 2 ways. It can be run in the platform where the plugin and its test code were compiled. Or else, if the compilation was done for a different target platform, then you will have to load the plugins and the examples to that target machine.

1. Run the example/test in the machine where it was compiled​

The plugins and the test code are output in the builddir directory. So provide the plugin path to Gstreamer before the test and the example pipeline are run.

# Pipeline
GST_PLUGIN_PATH=builddir gst-launch-1.0 ...

# Test app
GST_PLUGIN_PATH=builddir ./builddir/<test-app>

2. Run the example/test in a target machine​

Upload the plugin and test app to the target platform. Here, we use the adb utility.

# Push the plugin to the plugin directory
adb push builddir/libgstdctvrecord.so <plugin directory> # Eg: /usr/lib/gstreamer-1.0/

# Push the test apps to the execution directory
adb push builddir/<test-app> /tmp/

# Enter the adb shell and execute them
adb shell
shell# /tmp/<test-app>
note

The examples shown here are run on the Host PC itself, where the compilation was done. In order to build on a different target machine, you will need to cross compile after setting up the respective toolchain.

Usage Examples​

warning

It is recommended to use dctvrecord inside a gstreamer application than using as a gst-launch argument in bash. Using it in application gives more user control to recording feature. If executing via gst-launch-1.0, ensure -e argument is added in pipeline to ensure EOS signal is passed into the pipeline when ctrl-C is pressed to stop the execution.

Manual Mode - Basic Recording​

Start and stop recording manually via property:

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480,framerate=30/1 ! \
  x264enc tune=zerolatency bitrate=2000 ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=0 location=/tmp/videos prefix=test recording=true -e

Output: /tmp/videos/test_2025_10_13_15_45_23_456.mp4

note

Setting recording=true in the pipeline command-line starts recording immediately. To control recording dynamically, use the API or modify the property at runtime.

Manual Mode - Without Prefix​

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480,framerate=30/1 ! \
  x264enc tune=zerolatency bitrate=2000 ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=0 location=/tmp/videos recording=true -e

Output: /tmp/videos/2025_10_13_15_46_12_789.mp4

AUTO Mode (MQTT-based Automatic Recording)​

note

AUTO mode requires an MQTT broker running and a publisher sending detection messages.

If using a remote MQTT broker, ensure that the broker has the capability to send messages to all ports (not just localhost as by default).

The following example runs in AUTO mode and automatically starts/stops recording based on object detection messages via MQTT:

# Start MQTT broker (in separate terminal)
mosquitto -v

# Run pipeline with AUTO mode (default broker: localhost:1883)
GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480,framerate=30/1 ! \
  x264enc tune=zerolatency bitrate=2000 ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=1 mqtt-topic=detections/camera1 \
  det-timeout=7.0 location=/tmp/videos prefix=auto auto-enable=true -e

To connect to a remote MQTT broker, specify host and port properties:

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480,framerate=30/1 ! \
  x264enc tune=zerolatency bitrate=2000 ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=1 host=192.168.1.100 port=1883  \
  mqtt-topic=detections/camera1 det-timeout=7.0 \
  location=/tmp/videos prefix=auto auto-enable=true -e

How it works:

  1. Plugin connects to MQTT broker (default: localhost:1883, or specified host:port)
  2. Subscribes to topic: detections/camera1
  3. When detection messages arrive with objects in detections array: Recording starts
  4. When no detections for 7 seconds (det-timeout): Recording stops
  5. If MQTT connection lost for 5 seconds: Recording stops

MQTT Message Format (JSON):

{
  "timestamp": 1234567890.123456,
  "detections": [
    {
      "class": "person",
      "class_index": 0,
      "confidence": 0.952,
      "bbox": {"x": 0.345, "y": 0.223, "width": 0.156, "height": 0.445}
    },
    {
      "class": "car",
      "class_index": 2,
      "confidence": 0.874,
      "bbox": {"x": 0.678, "y": 0.512, "width": 0.234, "height": 0.167}
    }
  ]
}

Output Files:

  • /tmp/videos/auto_2025_10_13_16_10_45_123.mp4 (recording 1)
  • /tmp/videos/auto_2025_10_13_16_15_22_456.mp4 (recording 2)
  • ... (one file per recording session)

AUTO Mode - With Real Camera​

For production use with a real camera (e.g., v4l2):

# Using default localhost:1883 broker
GST_PLUGIN_PATH=builddir gst-launch-1.0 v4l2src device=/dev/video0 ! \
  video/x-raw,format=YUY2,width=1920,height=1080,framerate=30/1 ! \
  videoconvert ! \
  x264enc tune=zerolatency bitrate=5000 speed-preset=fast ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=1 mqtt-topic=detections/camera1 \
  det-timeout=10.0 location=/home/user/recordings prefix=cam1 auto-enable=true -e

# Using remote broker
GST_PLUGIN_PATH=builddir gst-launch-1.0 v4l2src device=/dev/video0 ! \
  video/x-raw,format=YUY2,width=1920,height=1080,framerate=30/1 ! \
  videoconvert ! \
  x264enc tune=zerolatency bitrate=5000 speed-preset=fast ! \
  h264parse config-interval=-1 ! \
  video/x-h264,stream-format=avc,alignment=au ! \
  dctvrecord mode=1 host=192.168.1.50 port=1883  \
  mqtt-topic=detections/camera1 det-timeout=10.0 \
  location=/home/user/recordings prefix=cam1 auto-enable=true -e

Test Applications​

The plugin provides four test applications to validate functionality:

1. Comprehensive Self-Test (selftest)​

Automated test suite that validates all plugin functionalities:

# Using Meson build
GST_PLUGIN_PATH=builddir ./builddir/selftest

What it tests:

  • Manual mode recording with prefix
  • Manual mode multiple recording cycles
  • Auto mode recording with MQTT (with configurable host/port)
  • Auto mode with auto-enable control
  • Auto mode multiple recording cycles
  • API get/set functions for all properties
  • Runtime property modification

Requirements:

  • mosquitto broker must be running for AUTO mode tests: mosquitto -v
  • Test files created in /tmp/dctvrecord_selftest/

MQTT Configuration: By default, the selftest connects to localhost:1883. To test with a different broker:

  • Modify the mqtt_broker and mqtt_port variables in the selftest source code
  • Or ensure your MQTT broker is accessible at localhost:1883

Output: The test suite provides detailed pass/fail results for each test case with color-coded output showing test progress and final summary.

2. Interactive API Test (test_api_dctvrecord)​

Interactive test application demonstrating the API usage in both MANUAL and AUTO modes. This test uses the API wrapper functions.

# Using Meson build - with command-line arguments
GST_PLUGIN_PATH=builddir ./builddir/test_api_dctvrecord [location] [prefix] [mode]

# Using Meson build - interactive prompts
GST_PLUGIN_PATH=builddir ./builddir/test_api_dctvrecord

Arguments:

  • location - Directory to save recordings (default: /tmp/dctvrecord_apitest)
  • prefix - Filename prefix (default: apitest)
  • mode - Recording mode: 0=MANUAL, 1=AUTO (default: 0)

MANUAL Mode Example:

GST_PLUGIN_PATH=builddir ./builddir/test_api_dctvrecord /tmp/test cam1 0

Commands:

  • r - Start recording
  • s - Stop recording
  • i - Show status (Shows the property values related to manual mode)
  • h - Show help
  • q - Quit

AUTO Mode Example:

GST_PLUGIN_PATH=builddir ./builddir/test_api_dctvrecord /tmp/test cam1 1

When started in AUTO mode, the application will interactively prompt for:

  • MQTT broker host (default: localhost)
  • MQTT broker port (default: 1883)
  • MQTT topic to subscribe to (no default - must be provided)
  • Detection timeout in seconds (default: 10.0)

Commands:

  • e - Enable auto-recording
  • d - Disable auto-recording
  • i - Show status (Shows the property values related to AUTO mode including MQTT configuration)
  • h - Show help
  • q - Quit

AUTO Mode Requirements:

  • mosquitto broker running: mosquitto -v
  • MQTT publisher sending detections to the configured topic
  • Ensure broker host and port are accessible

3. Interactive GStreamer Test (test_gst_dctvrecord)​

Interactive test application demonstrating GStreamer API usage (g_object_set/g_object_get) in both MANUAL and AUTO modes. This test uses GStreamer's native property functions directly without the API wrapper layer.

# Using Meson build - with command-line arguments
GST_PLUGIN_PATH=builddir ./builddir/test_gst_dctvrecord [location] [prefix] [mode]

# Using Meson build - interactive prompts
GST_PLUGIN_PATH=builddir ./builddir/test_gst_dctvrecord

Arguments:

  • location - Directory to save recordings (default: /tmp/dctvrecord_gsttest)
  • prefix - Filename prefix (default: gsttest)
  • mode - Recording mode: 0=MANUAL, 1=AUTO (default: 0)

MANUAL Mode Example:

GST_PLUGIN_PATH=builddir ./builddir/test_gst_dctvrecord /tmp/test cam1 0

Commands:

  • r - Start recording
  • s - Stop recording
  • i - Show status (Shows the property values related to manual mode)
  • h - Show help
  • q - Quit

AUTO Mode Example:

GST_PLUGIN_PATH=builddir ./builddir/test_gst_dctvrecord /tmp/test cam1 1

When started in AUTO mode, the application will interactively prompt for:

  • MQTT broker host (default: localhost)
  • MQTT broker port (default: 1883)
  • MQTT topic to subscribe to (no default - must be provided)
  • Detection timeout in seconds (default: 10.0)

Commands:

  • e - Enable auto-recording
  • d - Disable auto-recording
  • i - Show status (Shows the property values related to AUTO mode including MQTT configuration)
  • h - Show help
  • q - Quit

AUTO Mode Requirements:

  • mosquitto broker running: mosquitto -v
  • MQTT publisher sending detections to the configured topic
  • Ensure broker host and port are accessible

Key Difference from test_api_dctvrecord:

  • Uses g_object_set() and g_object_get() directly
  • Demonstrates how to use the plugin without the API wrapper
  • Shows GStreamer function calls in log messages
  • Useful for understanding low-level GStreamer property manipulation

4. MQTT Publisher Utility (mqtt_publisher)​

Interactive MQTT publisher that simulates object detection messages for testing AUTO mode:

# Using Meson build
./builddir/mqtt_publisher <topic> [broker_host] [broker_port]

Examples:

# For test_api_dctvrecord in AUTO mode
./builddir/mqtt_publisher apitest/detections

# Custom broker and port
./builddir/mqtt_publisher mytest/detections localhost 1883

Controls:

  • SPACE - Toggle detections ON/OFF
  • Ctrl+C - Quit

Message Format: Publishes JSON messages every 1 second:

{
  "timestamp": 1234567890.123456,
  "detections": [
    {
      "class": "person",
      "class_index": 0,
      "confidence": 0.952,
      "bbox": {"x": 0.345, "y": 0.223, "width": 0.156, "height": 0.445}
    },
    {
      "class": "car",
      "class_index": 2,
      "confidence": 0.874,
      "bbox": {"x": 0.678, "y": 0.512, "width": 0.234, "height": 0.167}
    }
  ]
}

When detections are ON: dctvrecord with AUTO mode enabled will START recording. When detections are OFF (empty array): dctvrecord will STOP recording after det-timeout expires.

Complete AUTO Mode Testing Workflow​

Terminal 1: Start the test application in AUTO mode (using API wrapper)

GST_PLUGIN_PATH=builddir ./builddir/test_api_dctvrecord /tmp/test apitest 1
# When prompted, enter:
#   - MQTT broker host: localhost (or press Enter for default)
#   - MQTT broker port: 1883 (or press Enter for default)
#   - MQTT topic: apitest/detections
#   - Detection timeout: 5.0 (or press Enter for default 10.0)
# Press 'e' to enable auto-recording

Alternative - Using GStreamer API directly:

GST_PLUGIN_PATH=builddir ./builddir/test_gst_dctvrecord /tmp/test gsttest 1
# Enter the same MQTT configuration when prompted
# Press 'e' to enable auto-recording

Terminal 2: Run the MQTT publisher

# For test_api_dctvrecord
./builddir/mqtt_publisher apitest/detections

# For test_gst_dctvrecord
./builddir/mqtt_publisher gsttest/detections

# Press SPACE to start sending detections

Expected Behavior:

  • When detections are published (non-empty detections array), recording starts automatically
  • When no detections are published (empty detections array), recording stops after det-timeout seconds
  • Files are saved in /tmp/test/ with respective prefix:
    • apitest_YYYY_MM_DD_HH_MM_SS_MSS.mp4 (for test_api_dctvrecord)
    • gsttest_YYYY_MM_DD_HH_MM_SS_MSS.mp4 (for test_gst_dctvrecord)

Dependencies​

Core Dependencies (Always Required)​

  • GStreamer
  • GStreamer Base
  • GStreamer Video
  • Meson >= 0.54 (for Meson build)

Install on Ubuntu/Debian:

sudo apt-get install libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
                     libgstreamer-plugins-good1.0-dev meson ninja-build

MQTT Communication Dependencies (Required)​

The dctvrecord plugin requires MQTT support for AUTO mode functionality:

  • Mosquitto MQTT client library (libmosquitto-dev)
  • Mosquitto broker (for testing)

Install on Ubuntu/Debian:

sudo apt-get install libmosquitto-dev mosquitto mosquitto-clients
note

MQTT dependencies are required for AUTO mode (mode=1) which enables event-driven automatic recording based on object detection messages.

Troubleshooting​

Plugin Not Found​

If you get "no such element 'dctvrecord'" error:

# Check if plugin is in the path
export GST_PLUGIN_PATH=/path/to/builddir:$GST_PLUGIN_PATH

# Or for Makefile build
export GST_PLUGIN_PATH=/path/to/build/lib:$GST_PLUGIN_PATH

# Verify plugin is loaded
gst-inspect-1.0 dctvrecord

MQTT Connection Issues​

If AUTO mode fails to connect:

  1. Ensure mosquitto broker is running:

    mosquitto -v

  2. Check broker logs for connection attempts

  3. Verify topic name matches between publisher and plugin

  4. Check firewall settings if using remote broker

Recording Not Starting​

For AUTO mode:

  1. Verify auto-enable=true is set
  2. Ensure mqtt-topic is configured
  3. Check that detection messages are being published
  4. Verify JSON message format matches expected structure

For MANUAL mode:

  1. Ensure mode=0 is set
  2. Set recording=true to start

Permission Issues​

If files can't be written:

# Ensure directory exists and is writable
mkdir -p /tmp/videos
chmod 777 /tmp/videos

# Or use a directory you own
dctvrecord location=$HOME/videos ...
