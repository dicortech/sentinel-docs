Testing

The STT plugin provides test applications for validating speech recognition accuracy using Word Error Rate (WER) calculation. The tests process audio files offline and compare the recognition results against reference transcriptions.

Test Applications​

The STT plugin provides two test executables that are built as part of the STT plugin build process and installed to /usr/bin/tests/sentinel-sdk/stt/. Each test executable corresponds to one speech recognition engine:

1. Vosk STT Test (test_stt_vosk)​

Tests the Vosk speech recognition engine with WER (Word Error Rate) calculation.

Location: /usr/bin/tests/sentinel-sdk/stt/test_stt_vosk

./test_stt_vosk <model_path> <audio_file.wav> <reference.txt>

Arguments:

  • model_path - Path to Vosk model directory
  • audio_file.wav - WAV audio file (S16LE, 16kHz, mono)
  • reference.txt - Reference transcription for comparison

Example:

./test_stt_vosk \
  /home/root/models/stt/vosk/vosk-model-small-en-us-0.15 \
  /usr/bin/tests/sentinel-sdk/stt/sample.wav \
  /usr/bin/tests/sentinel-sdk/stt/sample.txt

What it does:

  • Loads the Vosk model
  • Reads the WAV file and validates format (16kHz, mono, 16-bit)
  • Processes audio in 4000-sample chunks (simulating streaming)
  • Shows partial and final recognition results as audio is processed
  • Calls finalize() at end of file to retrieve any remaining buffered text
  • Calculates WER by comparing with reference text
  • Returns exit code 0 if WER < 50%, else 1
Finalize Method

The Vosk backend's finalize() method is important for file-based processing. It retrieves any remaining text that Vosk has buffered but not yet returned as a final result. This ensures complete transcription when the audio stream ends.

Audio Format Requirements:

  • Format: S16LE (16-bit signed PCM)
  • Sample Rate: 16000 Hz
  • Channels: 1 (mono)

2. Whisper STT Test (test_stt_whisper)​

Tests the Whisper speech recognition engine with WER calculation.

Location: /usr/bin/tests/sentinel-sdk/stt/test_stt_whisper

./test_stt_whisper <model_path> <audio_file.wav> <reference.txt>

Arguments:

  • model_path - Path to Whisper GGML model file
  • audio_file.wav - WAV audio file (16kHz, mono)
  • reference.txt - Reference transcription for comparison

Example:

./test_stt_whisper \
  /home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin \
  /usr/bin/tests/sentinel-sdk/stt/sample.wav \
  /usr/bin/tests/sentinel-sdk/stt/sample.txt

What it does:

  • Loads the Whisper model with default settings (4 threads)
  • Configures batch mode (streaming=false) for file processing
  • Reads the WAV file and converts to F32LE format
  • Validates format (16kHz, mono)
  • Processes audio in 48000-sample chunks (3 seconds at 16kHz)
  • Accumulates all audio data during process_audio() calls
  • Calls finalize() at end of file to perform full transcription
  • Calculates WER by comparing with reference text
  • Returns exit code 0 if WER < 50%, else 1
Batch Mode vs Streaming Mode

The Whisper backend supports two processing modes via the streaming parameter:

  • Streaming mode (streaming=true, default): Processes audio chunks in real-time as they arrive. Suitable for live audio capture where immediate feedback is needed.
  • Batch mode (streaming=false): Accumulates all audio and processes the complete buffer on finalize(). Provides better quality results with no duplicate segments. The test application uses this mode for file processing.

For file-based testing, batch mode is recommended as it processes the entire audio at once, resulting in more accurate transcriptions.

Audio Format Requirements:

  • Input Format: 16-bit PCM (auto-converted to F32LE)
  • Sample Rate: 16000 Hz
  • Channels: 1 (mono)

Word Error Rate (WER) Calculation​

Both test applications calculate WER to measure recognition accuracy:

WER Formula:

WER = (Substitutions + Deletions + Insertions) / Total Words × 100%
Accuracy = 100% - WER

WER Interpretation:

  • WER < 10%: Excellent recognition
  • WER 10-20%: Good recognition
  • WER 20-30%: Acceptable recognition
  • WER 30-50%: Poor recognition (warning threshold)
  • WER > 50%: Very poor recognition (test fails)

Running Tests​

Using Installed Binaries​

If the plugin is installed via Yocto:

# Vosk test
./test_stt_vosk \
  /home/root/models/stt/vosk/vosk-model-small-en-us-0.15 \
  /usr/bin/tests/sentinel-sdk/stt/sample.wav \
  /usr/bin/tests/sentinel-sdk/stt/sample.txt

# Whisper test
./test_stt_whisper \
  /home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin \
  /usr/bin/tests/sentinel-sdk/stt/sample.wav \
  /usr/bin/tests/sentinel-sdk/stt/sample.txt

Using Custom Test Files​

You can test with your own audio files:

1. Prepare audio file (must be WAV, 16kHz, mono):

# Convert audio to required format using ffmpeg
ffmpeg -i input.mp3 -ar 16000 -ac 1 -sample_fmt s16 output.wav

2. Create reference transcription:

echo "this is the reference transcription text" > reference.txt

3. Run test:

# Vosk
./test_stt_vosk \
  /home/root/models/stt/vosk/vosk-model-small-en-us-0.15 \
  output.wav \
  reference.txt

# Whisper
./test_stt_whisper \
  /home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin \
  output.wav \
  reference.txt

Testing Different Models​

Vosk Models​

Test with small model (faster, lower accuracy):

./test_stt_vosk \

Integration Testing with GStreamer​

While the standalone tests validate the recognition engine, you should also test the full GStreamer pipeline:

Test TCP Backend​

Terminal 1: Run pipeline

# Vosk
gst-launch-1.0 filesrc location=/usr/bin/tests/sentinel-sdk/stt/sample.wav ! \
  wavparse ! \
  audioconvert ! \
  audioresample ! \
  audio/x-raw,format=S16LE,channels=1,rate=16000 ! \
  dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15 tcp-port=9999

# Whisper
gst-launch-1.0 filesrc location=/usr/bin/tests/sentinel-sdk/stt/sample.wav ! \
  wavparse ! \
  audioconvert ! \
  audioresample ! \
  audio/x-raw,format=F32LE,channels=1,rate=16000 ! \
  dctstt model=/home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin tcp-port=9999

Terminal 2: Connect and view results

nc localhost 9999

Test MQTT Backend​

Terminal 1: Start MQTT broker

mosquitto -v

Terminal 2: Subscribe to results

mosquitto_sub -h localhost -t stt/test -v

Terminal 3: Run pipeline

# Vosk
gst-launch-1.0 filesrc location=/usr/bin/tests/sentinel-sdk/stt/sample.wav ! \
  wavparse ! \
  audioconvert ! \
  audioresample ! \

  dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15 \
    mqtt-broker=localhost \
    mqtt-topic=stt/test

# Whisper
gst-launch-1.0 filesrc location=/usr/bin/tests/sentinel-sdk/stt/sample.wav ! \

Troubleshooting​

Test Executable Not Found​

The test executables are automatically built and installed to /usr/bin/tests/sentinel-sdk/stt/ as part of the STT plugin build process via the BitBake recipe.

# Check if test binaries are installed
ls -l /usr/bin/tests/sentinel-sdk/stt/test_stt_*

# Expected output:
# /usr/bin/tests/sentinel-sdk/stt/test_stt_vosk
# /usr/bin/tests/sentinel-sdk/stt/test_stt_whisper

Note: The test applications are built from the STT plugin's test/ subdirectory during the meson build process.

Model Not Found​

# Verify model paths
ls -la /home/root/models/stt/vosk/
ls -la /home/root/models/stt/whisper/

# Ensure models are installed
# Vosk: should see directories like vosk-model-small-en-us-0.15
# Whisper: should see .bin files like ggml-tiny.en-q5_1.bin

Audio Format Errors​

If you get format warnings:

# Check your WAV file format
file /usr/bin/tests/sentinel-sdk/stt/sample.wav

# Expected output:
# sample.wav: RIFF (little-endian) data, WAVE audio, Microsoft PCM, 16 bit, mono 16000 Hz

# Convert if needed
ffmpeg -i input.wav -ar 16000 -ac 1 -sample_fmt s16 output.wav

High WER (Poor Recognition)​

If WER is very high:

  1. Check audio quality:

    • Ensure clear speech with minimal background noise
    • Verify correct sample rate (16kHz)
    • Check that audio is not clipped or distorted

  2. Check reference text:

    • Ensure reference transcription exactly matches the audio
    • Use lowercase, no punctuation (WER normalizes text)

  3. Try different model:

    • Vosk: Try larger model (vosk-model-en-us-0.22-lgraph)
    • Whisper: Try larger model (ggml-base.en.bin or ggml-small.en.bin)

  4. Check language match:

    • Ensure model language matches audio language
    • Use language-specific models when available

Expected Performance​

Vosk (Small Model)​

  • Processing Speed: ~3-5x real-time
  • Memory Usage: ~150MB
  • Expected WER: 10-20% (clean speech)
  • Latency: Low (~100-200ms)

Whisper (Tiny Model)​

  • Processing Speed: ~2-3x real-time
  • Memory Usage: ~200MB
  • Expected WER: 5-15% (clean speech)
  • Latency: Medium (~200-500ms)
