Build Instructions

This guide covers building, installing, and testing the dctotrack object tracking plugin.

Prerequisites​

Required Dependencies​

The following packages must be installed before building:

  • GStreamer 1.0+

  • Eigen3

  • OpenCV 4

  • Meson Build System

  • Ninja

Optional Dependencies​

  • libmosquitto
    • Required only if MQTT support is enabled
    • MQTT client library for publishing tracking results

Installing Dependencies​

  • Ubuntu/Debian
  • Fedora/RHEL
  • Arch Linux
# Essential build tools
sudo apt-get update
sudo apt-get install -y build-essential meson ninja-build pkg-config

# GStreamer
sudo apt-get install -y \
    libgstreamer1.0-dev \
    libgstreamer-plugins-base1.0-dev \
    gstreamer1.0-plugins-base \
    gstreamer1.0-plugins-good

# Eigen3
sudo apt-get install -y libeigen3-dev

# OpenCV
sudo apt-get install -y libopencv-dev

# MQTT (optional)
sudo apt-get install -y libmosquitto-dev
# Essential build tools
sudo dnf install -y gcc gcc-c++ meson ninja-build pkg-config

# GStreamer
sudo dnf install -y \
    gstreamer1-devel \
    gstreamer1-plugins-base-devel

# Eigen3
sudo dnf install -y eigen3-devel

# OpenCV
sudo dnf install -y opencv-devel

# MQTT (optional)
sudo dnf install -y mosquitto-devel
# Essential build tools
sudo pacman -S base-devel meson ninja pkg-config

# GStreamer
sudo pacman -S gstreamer gst-plugins-base

# Eigen3
sudo pacman -S eigen

# OpenCV
sudo pacman -S opencv

# MQTT (optional)
sudo pacman -S mosquitto

Build Configuration​

The plugin uses Meson build system with configurable options.

Available Build Options​

OptionDescriptionValuesDefault
machMachine layer backendjson, protobufjson
commCommunication frameworkmqtt, nonemqtt
plugin_install_dirCustom plugin install directorypath(auto-detected)

Configure Build​

Navigate to the plugin source directory:

cd <path_to_sdk>/ai/object_track/

Configure with default options:

meson setup builddir

Configure with custom options:

  • Default (JSON + MQTT)
  • Without MQTT
  • Custom Install Directory
  • Debug Build
  • Release Build
meson setup builddir \
    -Dmach=json \
    -Dcomm=mqtt
meson setup builddir \
    -Dmach=json \
    -Dcomm=none
meson setup builddir \
    -Dmach=json \
    -Dcomm=mqtt \
    -Dplugin_install_dir=/usr/local/lib/gstreamer-1.0
meson setup builddir \
    --buildtype=debug \
    -Dmach=json \
    -Dcomm=mqtt
meson setup builddir \
    --buildtype=release \
    -Dmach=json \
    -Dcomm=mqtt

Build​

Compile the plugin:

meson compile -C builddir

Or using ninja directly:

ninja -C builddir

Build Output:

  • Plugin library: builddir/libgstdctotrack.so
  • API static library: builddir/libapidctotrack.a
  • Test executables:
    • builddir/test_dctotrack
    • builddir/test_api_dctotrack

Install​

Install the plugin system-wide:

sudo meson install -C builddir

This installs:

  • Plugin: <libdir>/gstreamer-1.0/libgstdctotrack.so
  • API library: <libdir>/libapidctotrack.a
  • Headers: <includedir>/apidctotrack.h

Verify Installation​

Check if GStreamer recognizes the plugin:

gst-inspect-1.0 dctotrack

Expected output should show plugin details, properties, and capabilities.

If plugin is not found:

# Add plugin directory to GST_PLUGIN_PATH
export GST_PLUGIN_PATH=/usr/local/lib/gstreamer-1.0:$GST_PLUGIN_PATH

# Or copy plugin manually
sudo cp builddir/libgstdctotrack.so /usr/lib/x86_64-linux-gnu/gstreamer-1.0/

Testing​

Basic Plugin Test​

Run the basic GStreamer test:

cd builddir
./test_dctotrack

This creates a simple pipeline with videotestsrc to verify the plugin loads correctly.

API Test​

Run the C API test application:

cd builddir
./test_api_dctotrack

This tests all API functions including configuration and property management.

Integration Test with OBD Plugin​

Test with actual detection data:

# Ensure OBD plugin is installed
gst-inspect-1.0 dctobd

# Run integration pipeline
gst-launch-1.0 -v \
    videotestsrc ! videoconvert ! video/x-raw,format=RGB \
    ! dctobd model=/path/to/model.synap \
    ! dctotrack output=text track-statistics=true \
    ! videoconvert ! autovideosink

MQTT Test​

If MQTT support is enabled, test publishing:

# Start MQTT broker (if not running)
mosquitto -v &

# Subscribe to tracking results in another terminal
mosquitto_sub -h localhost -t tracking/results -v

# Run pipeline with MQTT output
gst-launch-1.0 -v \
    videotestsrc ! videoconvert ! video/x-raw,format=RGB \
    ! dctobd model=/path/to/model.synap \
    ! dctotrack output=mqtt mqtt-broker=localhost mqtt-topic=tracking/results \
    ! videoconvert ! fakesink

Troubleshooting​

Plugin Not Found​

Problem: gst-inspect-1.0 dctotrack returns "No such element or plugin"

Solutions:

  1. Check plugin installation path:

    find /usr -name "libgstdctotrack.so" 2>/dev/null

  2. Add to GST_PLUGIN_PATH:

    export GST_PLUGIN_PATH=/path/to/plugin:$GST_PLUGIN_PATH

  3. Update GStreamer cache:

    gst-inspect-1.0 --gst-plugin-path=/path/to/plugin

Build Errors​

Problem: Missing dependency errors during meson setup

Solution: Install missing packages:

# Check which dependencies are missing
meson setup builddir

# Install missing packages using your package manager

Problem: Eigen3 not found

Solution:

# Ubuntu/Debian
sudo apt-get install libeigen3-dev

# Or set PKG_CONFIG_PATH if installed in custom location
export PKG_CONFIG_PATH=/path/to/eigen3/pkgconfig:$PKG_CONFIG_PATH

Problem: OpenCV version mismatch

Solution:

The build system tries OpenCV 4 first, then falls back to OpenCV 3. If both fail:

# Check installed version
pkg-config --modversion opencv4

# Or specify manually
export PKG_CONFIG_PATH=/path/to/opencv/lib/pkgconfig:$PKG_CONFIG_PATH

MQTT Connection Issues​

Problem: Plugin compiles but MQTT publishing fails

Solutions:

  1. Verify MQTT broker is running:

    mosquitto -v

  2. Test broker connectivity:

    mosquitto_pub -h localhost -t test -m "hello"
    mosquitto_sub -h localhost -t test

  3. Check firewall rules:

    sudo ufw allow 1883/tcp  # Ubuntu
    sudo firewall-cmd --add-port=1883/tcp --permanent  # Fedora

  4. Enable MQTT debug logging:

    GST_DEBUG=dctotrack:5 gst-launch-1.0 ... ! dctotrack output=mqtt ...

Runtime Errors​

Problem: "No tracking output" or empty results

Solutions:

  1. Verify OBD plugin produces metadata:

    GST_DEBUG=dctotrack:5 gst-launch-1.0 ... ! dctobd ... ! dctotrack output=text ...

  2. Check detection confidence thresholds:

    • DCTOBD plugin's threshold vs dctotrack's track-thresh
    • Ensure DCTOBD produces detections with sufficient confidence

  3. Enable statistics:

    gst-launch-1.0 ... ! dctotrack track-statistics=true ...

Development Build​

For plugin development and debugging:

Debug Build with Symbols​

meson setup builddir \
    --buildtype=debug \
    -Db_sanitize=address,undefined \
    -Dmach=json \
    -Dcomm=mqtt

meson compile -C builddir

Running with Debug Output​

GST_DEBUG=dctotrack:5 gst-launch-1.0 ... ! dctotrack ...

Debug levels:

  • 1: ERROR
  • 2: WARNING
  • 3: INFO
  • 4: DEBUG
  • 5: LOG (verbose)

Integration with dctobd Plugin​

The dctotrack plugin is designed to work seamlessly with the DCTOBD (Object Detection) plugin.

Required dctobd Configuration​

For proper tracking, configure DCTOBD plugin to:

  1. Set appropriate detection threshold:

    dctobd ... threshold=0.4

    (Should be ≤ dctotrack's track-thresh)

  2. Use compatible model:

    • Model should output class labels and bounding boxes
    • Normalized coordinates (0.0-1.0) or pixel coordinates

Complete Pipeline Example​

gst-launch-1.0 -v \
    v4l2src device=/dev/video0 ! \
    videoconvert ! video/x-raw,format=RGB,width=1280,height=720 ! \
    dctobd model=/path/to/model.synap threshold=0.4 ! \
    dctotrack track-thresh=0.5 high-thresh=0.6 match-thresh=0.8 \
              track-buffer=30 frame-rate=30 \
              output=both mqtt-broker=localhost mqtt-topic=tracking/camera1 \
              track-statistics=true ! \
    videoconvert ! autovideosink
