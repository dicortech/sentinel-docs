STT Plugin Overview

This page describes the Speech-to-Text (STT) Plugin, a GStreamer sink element that enables offline speech recognition on Sentinel SoM using either the Vosk or Whisper speech recognition frameworks.

Overview​

The STT Plugin provides a GStreamer sink element (dctstt) that performs real-time speech-to-text conversion on audio streams. It accepts 16kHz mono PCM audio input, runs either Vosk or Whisper speech recognition models, and outputs recognition results through multiple communication backends.

dctstt (Speech-to-Text Sink Element)

The dctstt element is a sink element that terminates an audio pipeline. It accepts audio input, performs speech recognition using either Vosk (S16LE format) or Whisper (F32LE format), and outputs text results through TCP, MQTT, or console output.

Key Features​

  1. Offline Speech Recognition - No internet connection required, all processing happens locally
  2. Dual Engine Support - Vosk for lightweight recognition or Whisper for higher accuracy (compile-time selection)
  3. Multiple Communication Backends - TCP JSON server, MQTT publishing, or console output (compile-time selection)
  4. Partial Results Support - Real-time streaming of partial recognition results during speech (Vosk only)
  5. Grammar Support - Can be configured with custom grammar for improved accuracy on specific vocabulary (Vosk)
  6. Voice Activity Detection - Built-in VAD for efficient processing (Whisper only)
  7. GStreamer Integration - Standard GStreamer element properties and bus messages
  8. Multi-language Support - Support for multiple languages through different models

Architecture​

The STT plugin follows a three-layer architecture for modularity and maintainability:

1. GStreamer Layer (gstdctstt.cpp)​

Handles GStreamer plugin implementation:

  • Pipeline integration and audio buffer processing
  • Property management (model path, communication settings, engine-specific options)
  • Bus message posting for recognition results
  • Sink pad for receiving audio data

2. Speech Recognition Engine Layer​

Two engines are available (compile-time selection):

Vosk Integration:

  • Vosk API - Lightweight offline speech recognition
  • Supports S16LE audio format (16-bit PCM)
  • Model loading from directory structure
  • Real-time partial results support
  • JSON result parsing

Whisper Integration:

  • Whisper.cpp - Higher accuracy offline speech recognition
  • Supports F32LE audio format (32-bit float PCM)
  • Model loading from GGML binary files
  • Built-in Voice Activity Detection (VAD)
  • Configurable processing parameters (threads, step-ms, length-ms)

3. Communication Layer (com/)​

Platform-specific output implementation with three backends:

  • TCP (comm_tcp.cpp) - JSON server on configurable port
  • MQTT (comm_mqtt.cpp) - Publish results to MQTT broker
  • Printf (comm_printf.cpp) - Console output for debugging
info

Both the speech recognition engine and communication backend are selected at compile-time using build options. Only one engine and one backend are compiled into the plugin at a time.

Quick Start​

Using Vosk (S16LE format)​

gst-launch-1.0 alsasrc device=hw:1,0 ! \
    audioconvert ! \
    audioresample ! \
    audio/x-raw,format=S16LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15

Using Whisper (F32LE format)​

gst-launch-1.0 alsasrc device=hw:1,0 ! \
    audioconvert ! \
    audioresample ! \
    audio/x-raw,format=F32LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin
note

Audio Format Requirements:

  • Vosk: S16LE (16-bit signed PCM), 1 channel, 16000 Hz
  • Whisper: F32LE (32-bit float PCM), 1 channel, 16000 Hz

Use audioconvert and audioresample to convert from other formats.

Supported Input Formats​

Vosk Engine​

  • Audio Format: S16LE (16-bit signed little-endian PCM)
  • Sample Rate: 16000 Hz
  • Channels: 1 (mono)
  • Layout: Interleaved

Whisper Engine​

  • Audio Format: F32LE (32-bit float little-endian PCM)
  • Sample Rate: 16000 Hz
  • Channels: 1 (mono)
  • Layout: Interleaved
tip

Use audioconvert and audioresample to convert stereo or different format audio to the required format for your chosen engine.

Requirements​

To use the STT Plugin, you will need the following dependencies installed on Sentinel SoM:

Runtime Dependencies​

  • GStreamer 1.0 runtime libraries
  • ALSA libraries (for audio capture)

For Vosk Engine:

  • Vosk library (libvosk.so) version 0.3.45 or compatible
  • Pre-trained Vosk speech recognition model (directory structure)

For Whisper Engine:

  • Whisper.cpp library
  • Pre-trained Whisper model in GGML format (.bin file)

Communication Backend Dependencies​

Depending on the compiled backend:

  • TCP Backend: No additional dependencies
  • MQTT Backend: libmosquitto (MQTT client library)
  • Printf Backend: No additional dependencies

Speech Recognition Models​

Vosk Models:

  • Installed Location: /home/root/models/stt/vosk/
  • Small Model: vosk-model-small-en-us-0.15 (~40MB)
  • Large Model: vosk-model-en-us-0.22-lgraph (~128MB)
  • Other Languages: Available at https://alphacephei.com/vosk/models
  • Model directory structure: 
    /home/root/models/stt/vosk/vosk-model-small-en-us-0.15/
    ├── am/
    ├── conf/
    ├── graph/
    ├── ivector/
    └── README

Whisper Models:

  • Installed Location: /home/root/models/stt/whisper/
  • Default Model: ggml-tiny.en-q5_1.bin (Tiny model, quantized)
  • Available Sizes: tiny, base, small, medium, large
  • Download from Whisper.cpp repository or Hugging Face

Communication Backends​

TCP Backend​

Runs a JSON server that clients can connect to and receive recognition results in real-time.

# VOSK with TCP backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=S16LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15 tcp-port=9999

# WHISPER with TCP backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=F32LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin tcp-port=9999

# Connect to receive results
nc localhost 9999

MQTT Backend​

Publishes recognition results to an MQTT topic for distributed processing.

# VOSK with MQTT backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=S16LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15 \
        mqtt-broker=localhost \
        mqtt-topic=stt/vosk

# WHISPER with MQTT backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=F32LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin \
        mqtt-broker=localhost \
        mqtt-topic=stt/whisper

# Subscribe to results
mosquitto_sub -h localhost -t stt/vosk

Printf Backend​

Outputs recognition results to console/stdout for debugging.

# VOSK with Printf backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=S16LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15

# WHISPER with Printf backend
gst-launch-1.0 alsasrc device=hw:1,0 ! audioconvert ! audioresample ! \
    audio/x-raw,format=F32LE,channels=1,rate=16000 ! \
    dctstt model=/home/root/models/stt/whisper/ggml-tiny.en-q5_1.bin

Output Format​

Recognition results are provided in JSON format:

Final Result:

{
  "text": "hello world"
}

Partial Result:

{
  "partial": "hello wo"
}

Bus Messages​

The plugin posts GStreamer bus messages for integration with applications:

Message Name: stt-final

Structure Fields:

  • text (string): The recognized text
  • json (string): Complete JSON result from the speech recognition engine

Example (C):

GstBus *bus = gst_element_get_bus(pipeline);
GstMessage *msg = gst_bus_timed_pop_filtered(bus, GST_CLOCK_TIME_NONE,
    GST_MESSAGE_ELEMENT);

if (msg && gst_message_has_name(msg, "stt-final")) {
    const GstStructure *s = gst_message_get_structure(msg);
    const gchar *text = gst_structure_get_string(s, "text");
    g_print("Recognized: %s\n", text);
}

Use Cases​

  1. Voice Command Systems: Wake word detection and command recognition
  2. Transcription Services: Audio file or live stream transcription
  3. Accessibility: Speech-to-text for hearing impaired
  4. IoT Devices: Voice control for embedded systems
  5. Security Systems: Voice authentication and logging

Performance Considerations​

Vosk Engine​

  • Model Size: Small models (~40MB) to large models (~1.8GB)
  • CPU Usage: Moderate (30-50% single core)
  • Real Time Factor: ~.5x, partial results available in real-time
  • Memory: 150MB - 2GB depending on model
  • Accuracy: Good (85-90%)

Whisper Engine​

  • Model Size: Tiny (~75MB) to Large (~3GB)
  • CPU Usage: Higher (50-100% multi-core depending on threads setting)
  • Real Time Factor: More than 1x
  • Memory: 200MB - 4GB depending on model
  • Accuracy: Excellent (95-98%)
  • VAD: Built-in voice activity detection reduces processing when no speech
