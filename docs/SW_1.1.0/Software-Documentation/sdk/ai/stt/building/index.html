Building the STT Plugin

This guide covers building the STT (Speech-to-Text) GStreamer plugin from source for both standalone development and Yocto integration. The plugin supports both Vosk and Whisper speech recognition engines through compile-time selection.

Prerequisites​

Build Dependencies​

You will need the following development packages:

  • GStreamer 1.0 development libraries
    • gstreamer-1.0
    • gstreamer-base-1.0
  • GLib 2.0
    • glib-2.0
    • gobject-2.0
  • Vosk library - Speech recognition engine
    • libvosk.so (version 0.3.45 recommended)
    • vosk_api.h header file
  • Build tools
    • meson (>= 0.55.0)
    • ninja-build
    • pkg-config
    • C++11 compatible compiler (g++ or clang)

Communication Backend Dependencies​

Depending on your chosen communication backend:

BackendDependencies
TCPNone (uses standard sockets)
MQTTlibmosquitto, libmosquitto-dev
PrintfNone

Build System Overview​

The STT plugin uses Meson as its build system, supporting:

  • Standalone development builds
  • Yocto/OE cross-compilation
  • Multiple communication backends
  • Optional Vosk and Whisper plugins

Build Configuration Options​

Meson Options​

Configure the build using -D flags with meson setup:

OptionTypeDefaultDescription
comm_backendchoicetcpCommunication backend: tcp, mqtt, or printf
build_voskbooleantrueBuild Vosk STT plugin
build_whisperbooleantrueBuild Whisper STT plugin (if available)
vosk_model_pathstring/home/root/models/stt/vosk/vosk-model-small-en-us-0.15Default Vosk model path
vosk_dirstring``Path to Vosk library (for Yocto builds)

Communication Backend Selection​

The backend is selected at compile-time:

# TCP backend (default) - JSON server
meson setup build -Dcomm_backend=tcp

# MQTT backend - Publish to MQTT broker
meson setup build -Dcomm_backend=mqtt

# Printf backend - Console output (debugging)
meson setup build -Dcomm_backend=printf
Important

The communication backend cannot be changed at runtime. You must rebuild the plugin to switch backends.

Standalone Development Build​

Step 1: Download Vosk Library​

For ARM64/aarch64 development:

cd sentinal_sdk/ai/STT/mach/vosk/
mkdir -p libs
cd libs

# Download Vosk for ARM64
wget https://github.com/alphacep/vosk-api/releases/download/v0.3.45/vosk-linux-aarch64-0.3.45.zip

# Extract
unzip vosk-linux-aarch64-0.3.45.zip

# Verify
ls vosk-linux-aarch64-0.3.45/
# Should contain: libvosk.so, vosk_api.h
note

For x86_64 development, use vosk-linux-x86_64-0.3.45.zip instead.

Step 2: Configure Build​

cd sentinal_sdk/ai/STT/

# Configure with TCP backend (default)
meson setup build

# Or configure with MQTT backend
meson setup build -Dcomm_backend=mqtt

# Or configure with specific options
meson setup build \
    -Dcomm_backend=tcp \
    -Dbuild_vosk=true \
    -Dbuild_whisper=false \
    -Dvosk_model_path=/home/root/models/stt/vosk/vosk-model-small-en-us-0.15

Step 3: Build​

# Build the plugin
ninja -C build

# The plugin will be at:
# build/mach/vosk/libgstdctstt.so

Step 4: Test the Plugin​

# Test that GStreamer can load the plugin
GST_PLUGIN_PATH=build/mach/vosk gst-inspect-1.0 dctstt

# Should display plugin information and properties

Step 5: Install (Optional)​

# Install to local GStreamer plugins directory
sudo cp build/mach/vosk/libgstdctstt.so \
    /usr/lib/aarch64-linux-gnu/gstreamer-1.0/

# Or install to custom location
mkdir -p ~/.local/lib/gstreamer-1.0/
cp build/mach/vosk/libgstdctstt.so ~/.local/lib/gstreamer-1.0/
export GST_PLUGIN_PATH=$HOME/.local/lib/gstreamer-1.0:$GST_PLUGIN_PATH

Cross-Compilation for Yocto​

The plugin is built automatically as part of the sentinel-sdk recipe in Yocto. The sentinel-sdk_1.0.0.bb recipe handles all dependencies and configuration.

Yocto Recipe Configuration​

The recipe supports PACKAGECONFIG options:

# Default: TCP backend
PACKAGECONFIG ??= "vosk-tcp"

# For MQTT backend
PACKAGECONFIG ??= "vosk-mqtt"

# For Printf backend
PACKAGECONFIG ??= "vosk-printf"

Edit meta-dctk-sentinel/recipes-multimedia/gstreamer/sentinel-sdk_1.0.0.bb to change the backend.

Building in Yocto​

# Clean previous builds (if needed)
bitbake -c cleansstate sentinel-sdk

# Build with selected backend
bitbake sentinel-sdk

# The plugin will be installed to:
# /usr/lib/gstreamer-1.0/libgstdctstt.so

Yocto Build Variables​

The recipe automatically configures:

VariableValueDescription
MESON_CROSS_FILEAuto-setCross-compilation configuration
vosk_dir${STAGING_LIBDIR}Vosk library location
comm_backendFrom PACKAGECONFIGTCP, MQTT, or Printf

Verifying the Build​

Check Plugin Registration​

# List all installed plugins
gst-inspect-1.0 dctstt

# Should output:
# Factory Details:
#   Rank                     none (0)
#   Long-name                Vosk Speech-to-Text Sink
#   Klass                    Sink/Audio
#   Description              Speech recognition using Vosk...

Check Communication Backend​

The compiled backend is shown in the plugin description:

gst-inspect-1.0 dctstt | grep -A 5 "Properties"

TCP Backend will show:

tcp-port            : TCP server port for JSON output

MQTT Backend will show:

mqtt-broker         : MQTT broker address
mqtt-port           : MQTT broker port
mqtt-topic          : MQTT topic for publishing results

Troubleshooting​

Vosk Library Not Found​

Error:

Vosk library not found at: .../libvosk.so

Solution:

  • Ensure Vosk library is downloaded and extracted to correct location
  • For standalone builds: Check mach/vosk/libs/vosk-linux-aarch64-0.3.45/
  • For Yocto builds: Ensure vosk recipe is built first

GStreamer Headers Not Found​

Error:

gstreamer-1.0 dependency not found

Solution:

# Install GStreamer development packages
sudo apt-get install \
    libgstreamer1.0-dev \
    libgstreamer-plugins-base1.0-dev

Communication Dependency Missing​

Error (MQTT):

mosquitto dependency not found

Solution:

# Install MQTT client library
sudo apt-get install libmosquitto-dev

Plugin Not Loaded by GStreamer​

Error:

no such element factory "dctstt"!

Solution:

# Check if plugin file exists
ls -la /usr/lib/*/gstreamer-1.0/libgstdctstt.so

# Check GStreamer plugin path
gst-inspect-1.0 --version

# Set plugin path explicitly
export GST_PLUGIN_PATH=/path/to/plugin:$GST_PLUGIN_PATH

Clean Build​

To start fresh:

# Remove build directory
rm -rf build/

# Reconfigure and rebuild
meson setup build -Dcomm_backend=tcp
ninja -C build

Build Scripts​

A convenience build script is provided:

# For standalone development
./build.sh

# The script will:
# 1. Check for Vosk library
# 2. Configure with Meson
# 3. Build with Ninja
# 4. Report status
