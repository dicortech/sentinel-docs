Tracking Parameters​

track-thresh​

Description: Minimum confidence threshold for starting a new track.

Type: float Range: 0.0 - 1.0 Default: 0.5

Detections with confidence below this threshold will not be used to initialize new tracks. However, they may still be used to update existing tracks (see high-thresh).

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack track-thresh=0.6 ! ...
api_dctotrack_set_track_thresh(element, 0.6);
g_object_set(G_OBJECT(element), "track-thresh", 0.6f, NULL);

high-thresh​

Description: High confidence threshold for first-stage association.

Type: float Range: 0.0 - 1.0 Default: 0.6

In the ByteTrack algorithm, detections are separated into high and low confidence. High-confidence detections (above this threshold) are matched first to existing tracks. Low-confidence detections are then used to recover lost tracks.

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack high-thresh=0.7 ! ...
api_dctotrack_set_high_thresh(element, 0.7);
g_object_set(G_OBJECT(element), "high-thresh", 0.7f, NULL);

match-thresh​

Description: IoU (Intersection over Union) threshold for matching detections to tracks.

Type: float Range: 0.0 - 1.0 Default: 0.8

When a detection and a predicted track position have an IoU above this threshold, they are considered as a potential match. Higher values require more overlap for matching.

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack match-thresh=0.75 ! ...
api_dctotrack_set_match_thresh(element, 0.75);
g_object_set(G_OBJECT(element), "match-thresh", 0.75f, NULL);

track-buffer​

Description: Number of frames to keep lost tracks before removing them permanently.

Type: int Range: 1 - 1000 Default: 30

When a track is not matched to any detection, it enters the "Lost" state. If it remains unmatched for more frames than this buffer size, it will be permanently removed. Increase this value for scenarios with frequent occlusions.

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack track-buffer=50 ! ...
api_dctotrack_set_track_buffer(element, 50);
g_object_set(G_OBJECT(element), "track-buffer", 50, NULL);

frame-rate​

Description: Expected frame rate of the video source in frames per second (fps).

Type: int Range: 1 - 240 Default: 30

This value is used by the Kalman filter for motion prediction. Set it to match your actual video frame rate for accurate prediction.

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack frame-rate=60 ! ...
api_dctotrack_set_frame_rate(element, 60);
g_object_set(G_OBJECT(element), "frame-rate", 60, NULL);

Output Configuration​

output​

Description: Output mode for tracking results.

Type: string Valid Values: "none", "text", "mqtt", "both" Default: "text"

  • none: Silent mode, no output generated
  • text: JSON output to stdout (human-readable)
  • mqtt: Publish results to MQTT broker
  • both: Text + MQTT simultaneously
  • gst-launch
  • C API
  • GObject Property
# Text output
gst-launch-1.0 ... ! dctotrack output=text ! ...

# MQTT output
gst-launch-1.0 ... ! dctotrack output=mqtt ! ...

# Both outputs
gst-launch-1.0 ... ! dctotrack output=both ! ...

# No output (silent)
gst-launch-1.0 ... ! dctotrack output=none ! ...
api_dctotrack_set_output_mode(element, "mqtt");
g_object_set(G_OBJECT(element), "output", "mqtt", NULL);

output-format​

Description: Format of the output JSON structure.

Type: string Valid Values: "tracking", "detection" Default: "tracking"

  • tracking: Separate tracks array with track_id, state, and detection info

    {"timestamp": X, "tracks": [{track_id, class, confidence, bbox, state}, ...]}

  • detection: Detection format with track_id merged into each detection

    {"timestamp": X, "detections": [{class, confidence, bbox, track_id}, ...]}
  • gst-launch
  • C API
  • GObject Property
# Tracking format
gst-launch-1.0 ... ! dctotrack output-format=tracking ! ...

# Detection format
gst-launch-1.0 ... ! dctotrack output-format=detection ! ...
api_dctotrack_set_output_format(element, "detection");
g_object_set(G_OBJECT(element), "output-format", "detection", NULL);

MQTT Configuration​

These properties are only relevant when output is set to "mqtt" or "both".

Type: string Default: "localhost"

  • C API
  • GObject Property

api_dctotrack_set_mqtt_broker(element, "192.168.1.100");
g_object_set(G_OBJECT(element), "mqtt-broker", "192.168.1.100", NULL);

mqtt-port​

Description: MQTT broker port number.

Type: int Range: 1 - 65535 Default: 1883

  • gst-launch
  • C API
  • GObject Property

api_dctotrack_set_mqtt_port(element, 8883);
g_object_set(G_OBJECT(element), "mqtt-port", 8883, NULL);

mqtt-topic​

Description: MQTT topic to publish tracking results.

Type: string Default: "tracking/results"

  • gst-launch
  • C API
  • GObject Property

api_dctotrack_set_mqtt_topic(element, "camera1/tracking");

Monitoring​

track-statistics​

Description: Enable detailed tracking statistics logging.

Type: boolean Default: false

When enabled, the plugin logs detailed statistics about track states, counts, and processing metrics to the console.

  • gst-launch
  • C API
  • GObject Property
gst-launch-1.0 ... ! dctotrack track-statistics=true ! ...
api_dctotrack_set_track_statistics(element, true);
g_object_set(G_OBJECT(element), "track-statistics", TRUE, NULL);

Configuration Examples​

Surveillance System (High Accuracy)​

gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobd model-path=/path/to/model.synap \
  ! dctotrack \
      track-thresh=0.6 \
      high-thresh=0.7 \
      match-thresh=0.85 \
      track-buffer=50 \
      frame-rate=30 \
      output=mqtt \
      mqtt-broker=192.168.1.100 \
      mqtt-topic=surveillance/tracking \
  ! videoconvert ! autovideosink

Real-time Processing (Performance Optimized)​

gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobd model-path=/path/to/model.synap \
  ! dctotrack \
      track-thresh=0.4 \
      high-thresh=0.5 \
      match-thresh=0.7 \
      track-buffer=20 \
      frame-rate=60 \
      output=none \
  ! videoconvert ! autovideosink

Crowded Scene (Frequent Occlusions)​

gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobd model-path=/path/to/model.synap \
  ! dctotrack \
      track-thresh=0.5 \
      high-thresh=0.6 \
      match-thresh=0.75 \
      track-buffer=100 \
      frame-rate=30 \
      output=both \
      mqtt-broker=localhost \
      mqtt-topic=crowd/tracking \
      track-statistics=true \
  ! videoconvert ! autovideosink

Querying Properties at Runtime​

You can inspect current property values using gst-inspect-1.0:

# List all properties
gst-inspect-1.0 dctotrack

# Query specific property via pipeline
gst-launch-1.0 ... ! dctotrack name=tracker ! ... &
# Then use gst-launch-1.0 with --gst-debug to see property values

Using C API:

float track_thresh;
api_dctotrack_get_track_thresh(element, &track_thresh);
printf("Current track-thresh: %.2f\n", track_thresh);

Using GObject:

gfloat track_thresh;
g_object_get(G_OBJECT(element), "track-thresh", &track_thresh, NULL);
g_print("Current track-thresh: %.2f\n", track_thresh);

Tips for Tuning​

  1. track-thresh vs high-thresh:

    • Keep high-thresh ≥ track-thresh
    • Larger gap allows more recovery of lost tracks from low-confidence detections

  2. match-thresh:

    • Lower values (0.6-0.7): Better for fast-moving objects with imperfect detection
    • Higher values (0.8-0.9): Better for static/slow scenes with accurate detection

  3. track-buffer:

    • Short buffer (10-20): Fast removal of disappeared objects
    • Long buffer (50-100): Better recovery from occlusions

  4. frame-rate:

    • Always match your actual video FPS for accurate motion prediction
    • Incorrect value leads to poor prediction and ID switches

  5. output modes:

    • Use none when tracking data is consumed internally (metadata passing)
    • Use mqtt for multi-system integration and real-time monitoring
    • Use both during development/debugging
