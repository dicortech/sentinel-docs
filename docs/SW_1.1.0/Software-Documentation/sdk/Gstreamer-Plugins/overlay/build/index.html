Build and Test

For building the Gstreamer plugins, we use the Meson build system as it is the one promoted by Gstreamer. The plugin supports multiple rendering backends through the machine layer.

note

Make sure that the toolchain is setup, if you are building for the Sentinel.

Build with Meson​

Basic Build (OpenCV Backend)​

# Remove any build directory if already present:
rm -rf builddir/

# Setup build directory (default: MACH=opencv)
meson setup builddir

# Compile
ninja -C builddir

Once the compilation is done, the following files among others should be generated in the builddir.

builddir/                   # Build directory
└── libgstdctoverlay.so     # GStreamer plugin

Build Options​

The plugin supports multiple build configuration options:

Machine Layer Selection​

Since this plugin is implemented in a layered architecture, support for additional rendering backends can be added in mach/ layer of the plugin source. To build the plugin for a specific machine, issue the following command:

# Explicitly specify machine layer
meson setup builddir -DMACH=<machine-name>

Running the examples​

The examples can be run in 2 ways. It can be run in the platform where the plugin and its test code were compiled. Or else, if the compilation was done for a different target platform, then you will have to load the plugins to that target machine.

1. Run the example in the machine where it was compiled​

The plugins are output in the builddir directory. So provide the plugin path to Gstreamer before the example pipeline is run.

# Pipeline
GST_PLUGIN_PATH=builddir gst-launch-1.0 ...

2. Run the example in a target machine​

Upload the plugin to the target platform. Here, we use the adb utility.

# Push the plugin to the plugin directory
adb push builddir/libgstdctoverlay.so /usr/lib/gstreamer-1.0/

# Verify installation
adb shell gst-inspect-1.0 dctoverlay
note

The examples shown here demonstrate usage on both host and target platforms.

Usage Examples​

Basic Detection Overlay​

The following example displays detection overlays with default styling.

# Start MQTT broker (in separate terminal)
mosquitto -v

# Run pipeline with overlay
gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay mqtt-host=localhost mqtt-topic=detections ! \
  videoconvert ! autovideosink

What it does:

  • Captures video from /dev/video8
  • Converts to BGR format
  • Receives detection data via MQTT from detections topic
  • Draws bounding boxes and labels
  • Displays video with overlays

Custom Box and Font Styling​

The following example uses green boxes with yellow text.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-topic=detections \
    box-color-r=0 box-color-g=255 box-color-b=0 \
    box-thickness=2 \
    font-scale=0.6 \
    font-color-r=255 font-color-g=255 font-color-b=0 \
    font-thickness=2 ! \
  videoconvert ! autovideosink

What it does:

  • Green bounding boxes (RGB: 0, 255, 0)
  • Yellow text (RGB: 255, 255, 0)
  • Box thickness: 2 pixels
  • Font scale: 0.6

Label Background Customization​

The following example adds semi-transparent black backgrounds to labels.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-topic=detections \
    draw-label-background=true \
    label-bg-color-r=0 label-bg-color-g=0 label-bg-color-b=0 \
    label-bg-alpha=0.7 \
    label-position=0 ! \
  videoconvert ! autovideosink

What it does:

  • Black label background (RGB: 0, 0, 0)
  • 70% opacity (alpha: 0.7)
  • Labels positioned at top-left of boxes

Confidence Display Configuration​

The following example shows confidence scores with 2 decimal places.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-topic=detections \
    show-confidence=true \
    confidence-decimals=2 ! \
  videoconvert ! autovideosink

What it does:

  • Displays confidence scores in labels
  • Shows 2 decimal places (e.g., "0.95")

ROI Visualization​

The following example draws a Region of Interest rectangle.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-topic=detections \
    enable-roi=true \
    roi-x=100 roi-y=100 roi-width=400 roi-height=300 \
    roi-color-r=255 roi-color-g=255 roi-color-b=0 \
    roi-thickness=2 ! \
  videoconvert ! autovideosink

What it does:

  • Draws yellow ROI rectangle (RGB: 255, 255, 0)
  • ROI position: (100, 100) with 400x300 size
  • ROI thickness: 2 pixels

Class Filtering​

The following example only displays specific object classes.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-topic=detections \
    enable-class-filter=true \
    filter-class-ids="0,1,2,5" ! \
  videoconvert ! autovideosink

What it does:

  • Only draws detections for class IDs 0, 1, 2, and 5
  • Filters out all other classes

Complete Configuration Example​

The following example demonstrates all customization options.

gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay \
    mqtt-host=localhost \
    mqtt-port=1883 \
    mqtt-topic=detections \
    mqtt-qos=1 \
    box-color-r=0 box-color-g=255 box-color-b=0 \
    box-thickness=2 \
    font-type=0 \
    font-scale=0.6 \
    font-color-r=255 font-color-g=255 font-color-b=0 \
    font-thickness=2 \
    draw-label-background=true \
    label-bg-color-r=0 label-bg-color-g=0 label-bg-color-b=0 \
    label-bg-alpha=0.7 \
    label-position=0 \
    show-confidence=true \
    confidence-decimals=2 \
    enable-roi=true \
    roi-x=100 roi-y=100 roi-width=400 roi-height=300 \
    roi-color-r=255 roi-color-g=255 roi-color-b=0 \
    roi-thickness=2 \
    enable-class-filter=true \
    filter-class-ids="0,1,2" ! \
  videoconvert ! autovideosink

Publishing Detection Data via MQTT​

To test the overlay plugin, you need to publish detection data to MQTT. Here's an example Python script:

#!/usr/bin/env python3
import paho.mqtt.client as mqtt
import json
import time

# Create MQTT client
client = mqtt.Client()
client.connect("localhost", 1883, 60)

# Sample detection data
detections = {
    "detections": [
        {
            "bbox": {"x": 100, "y": 50, "width": 200, "height": 150},
            "label": "person",
            "confidence": 0.95,
            "class_id": 0
        },
        {
            "bbox": {"x": 400, "y": 200, "width": 150, "height": 180},
            "label": "car",
            "confidence": 0.87,
            "class_id": 2
        }
    ]
}

Debugging​

To enable detailed debug output from the plugin, set the GST_DEBUG environment variable before running the pipeline:

export GST_DEBUG=dctoverlay:5

After setting the debug level, run your pipeline to see detailed log messages:

GST_DEBUG=dctoverlay:5 gst-launch-1.0 v4l2src device=/dev/video8 ! videoconvert ! \
  video/x-raw,format=BGR ! \
  dctoverlay mqtt-host=localhost mqtt-topic=detections ! \
  videoconvert ! autovideosink

Debug levels range from 0 (no output) to 5 (verbose logging). Level 5 provides the most detailed information for troubleshooting.

note

If you encounter issues with the plugin:

  • Verify MQTT broker is running: mosquitto -v
  • Check MQTT connection: mosquitto_sub -h localhost -t detections
  • Verify video format is BGR (not RGB)
  • Ensure all dependencies are properly installed

Verifying Installation​

# Check if plugin is installed
gst-inspect-1.0 dctoverlay

# Verify properties
gst-inspect-1.0 dctoverlay | grep -A 5 "Plugin Details"
