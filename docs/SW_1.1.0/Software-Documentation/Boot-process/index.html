Boot Process

The Sentinel SOM SL1680 MK1 supports two distinct boot modes, allowing flexibility based on storage preference and application requirements:

  • SD Card mode

In this mode, the system boots directly from a microSD card inserted into the designated slot. This method is ideal for development, testing, or scenarios where storage needs to be easily removable or replaceable.

  • eMMC mode

This mode enables the system to boot from its onboard embedded MultiMediaCard (eMMC) storage. It is typically used for production environments where more permanent and reliable storage is required.

The way of booting can be controlled by SW1 switch as shown in the below figure.

SD card mode​

When SW1 is in ON position, the board will boot in SD card mode. In this mode, the device will load the U-boot stored in the internal SPI flash and will boot up the linux kernel and rootfs present in the SD card. This mode requires an SD card compatible image to be flashed in the SD card which is discussed in this section.

If no SD card is found, the device will stay in the command line of U-boot.

eMMC mode​

When SW1 is in OFF position, the board will boot in eMMC mode. The device will load the U-boot stored in the eMMC and will further boot up the Linux kernel and rootfs present in eMMC.

TFTP Kernel Boot + NFS RootFS Setup​

This section documents the support for TFTP-based kernel loading and NFS-based root filesystem mounting for the Sentinel SOM.

1. Setting Up the Server for NFS RootFS​

Pre-requisites​

Install the NFS server package on your Linux host:

sudo apt install nfs-kernel-server

Steps​

  1. Download nfs_srv_setup.sh script from Gerrit to the directory containing your rootfs.subimg.gz and home.subimg.gz.
  2. Run the setup script:
sudo ./nfs_srv_setup.sh <rootfs_mountpoint> <nfs_set>

Where:

  • <rootfs_mountpoint> — directory where the SOM rootfs will be hosted.
  • <nfs_set> — set to y when initializing the NFS server for the first time.

Example:

sudo ./nfs_srv_setup.sh /mnt/rootfs y
note

In nfs_srv_setup.sh the subnet is set as 192.168.0.0/16. User can change the subnet as per the need.

2. Setting Up TFTP Boot for the Kernel (Server Side)​

Pre-requisites​

Install the TFTP server:

sudo apt install tftpd-hpa

Configure TFTP Server​

Edit /etc/default/tftpd-hpa and add:

TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/var/lib/tftpboot"
TFTP_ADDRESS=":69"
TFTP_OPTIONS="--secure"

Set up TFTP directory​

sudo mkdir -p /srv/tftp
sudo chown -R tftp:tftp /srv/tftp
sudo chmod -R 755 /srv/tftp

Restart service:

sudo systemctl restart tftpd-hpa

Copy Kernel Boot Image​

Copy boot.subimg from SYNAIMG to the TFTP directory:

cp boot.subimg /srv/tftp/

3. Setting Up TFTP Boot on the SOM (Client Side)​

Configure Network in U-Boot​

In the U-Boot console:

setenv serverip <tftp_server_ip>
setenv ipaddr <som_ip_address>
saveenv

Boot Using TFTP​

netboot <start_address> <dtb_offset> <file_name>

Where:

  • <start_address> — recommended: 0x20000000
  • <dtb_offset> — offset of the DTB inside boot.subimg
  • <file_name> — TFTP-available boot image filename

Extract DTB offset:

binwalk boot.subimg | grep "Flattened device tree" | awk '{print $2}'
note

In astra SDK 1.8.0 instead of using the netboot command please use the fillowing command:

tftpboot 0x20000000 boot.subimg
bootram 0x20000000

4. Setting NFS RootFS on SOM​

To boot kernel with NFS rootfs, configure two variables in U‑Boot.

1. Enable Bootargs Override​

setenv bootargscontrol y

2. Set Bootargs for NFS RootFS​

setenv bootargs 'console=ttyS0,115200 root=/dev/nfs nfsroot=<nfs_server_ip>:<nfs_rootfs_folder>,nfsvers=3,tcp,rw ip=<som_ip>:<server_ip>:<gateway_ip>:<netmask>::eth0:off'

Example:

setenv bootargs 'console=ttyS0,115200 root=/dev/nfs \
nfsroot=192.168.1.102:/mnt/rootfs,nfsvers=3,tcp,rw \
ip=192.168.1.110:192.168.1.102:192.168.1.1:255.255.0.0::eth0:off'

By default, bootargs normally point to the SD card partitions. Setting the above overrides them for NFS boot.
