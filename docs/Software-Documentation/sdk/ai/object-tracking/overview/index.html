Overview

A modular GStreamer plugin for AI-powered multi-object tracking using the ByteTrack algorithm with support for real-time video tracking, MQTT integration, and flexible output formats.

Architecture​

The plugin library is organized into different layers.

  • GST Layer - The GST layer has the main Gstreamer related functionalities. However, the functional tasks which can be offloaded to different hardware is kept in the machine layer.

  • Machine Layer - This is the layer where machine specific operations are implemented. This is done to port the plugin easily to different platforms. Currently supports JSON parsing with extensibility for Protocol Buffers and other formats.

  • Communication Layer - This layer handles the communication of the plugin to the external world. It publishes tracking results via MQTT or other protocols.

  • API Layer - The API layer is a wrapper layer using which the user can configure the gstreamer plugin. This is not part of the gstreamer framework. Instead of the API layer, the user can use gstreamer's APIs directly too.

Folder Structure​

The corresponding folder structure is as follows:

inc/                   # Header files
├── gst/               # GStreamer layer (plugin interface)
├── mach/              # Machine layer (detection parsing)
├── comm/              # Communication layer (MQTT integration)
├── api/               # API layer (C interface)
└── lib/               # ByteTrack library (tracking algorithms)

src/                   # Source files
├── gst/               # GStreamer implementation
├── mach/              # Machine implementations (json parser, etc.)
├── comm/              # Communication implementation (MQTT)
├── api/               # API implementation
└── lib/               # ByteTrack algorithm implementation

test/                  # Test applications
├── test_dctotrack.c   # Basic GStreamer pipeline test
└── api/
    └── test_api_dctotrack.c  # API-based test application

Plugin Elements​

This plugin provides one GStreamer element:

dctotrack (Detection to Tracking Transform)​

Transform element that performs multi-object tracking on incoming video frames with detection metadata. It accepts video frames with detection results attached as metadata, runs the ByteTrack algorithm, and outputs the video frames with tracking results.

Capabilities:

  • Input: video/x-raw with detection metadata
  • Output: video/x-raw with tracking results

Features​

This gstreamer plugin has the following features/functionalities:

Tracking Algorithm​

  • ByteTrack Implementation:
    • State-of-the-art multi-object tracking algorithm
    • Kalman filtering for motion prediction
    • IoU (Intersection over Union) based data association
    • Linear Assignment Problem (LAPJV) solver for optimal matching
    • Four-state track management (New, Tracked, Lost, Removed)

Detection Integration​

  • Metadata Processing:
    • Seamless integration with DCTOBD detection plugin
    • JSON-based detection data parsing
    • Support for normalized and pixel coordinates
    • Extensible for Protocol Buffers and other formats

Tracking Control​

  • Configurable Thresholds:
    • Track threshold (minimum confidence to start tracking)
    • High threshold for first association
    • IoU match threshold for track-detection matching
    • Track buffer (frames to keep lost tracks)
    • Frame rate configuration for motion prediction

Output Modes​

  • Flexible Output Options:
    • None: Silent tracking (no output)
    • Text: Human-readable JSON to stdout
    • MQTT: Real-time publishing to MQTT broker
    • Both: Text + MQTT simultaneously

Output Formats​

  • Tracking Format:

    {
      "timestamp": 384265.253688,
      "tracks": [
        {
          "track_id": 1,
          "class": "person",
          "class_index": 0,
          "confidence": 0.871,
          "bbox": {"x": 0.323, "y": 0.357, "width": 0.461, "height": 0.642},
          "state": "Tracked"
        }
      ]
    }

  • Detection Format:

    {
      "timestamp": 384265.253688,
      "detections": [
        {
          "class": "person",
          "class_index": 0,
          "confidence": 0.871,
          "bbox": {"x": 0.323, "y": 0.357, "width": 0.461, "height": 0.642},
          "track_id": 1
        }
      ]
    }

MQTT Integration​

  • Real-time Publishing:
    • Configurable broker address and port
    • Custom topic configuration
    • QoS support
    • Connection management with retry
    • Asynchronous publishing

Integration Example​

  • gst-launch Command
  • C API
# Basic tracking with text output
gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobdmodel-path=/path/to/model.synap \
  ! dctotrack track-thresh=0.5 output=text \
  ! videoconvert ! autovideosink

# Tracking with MQTT publishing
gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobdmodel-path=/path/to/model.synap \
  ! dctotrack track-thresh=0.5 output=mqtt \
      mqtt-broker=192.168.1.100 mqtt-topic=tracking/results \
  ! videoconvert ! autovideosink

# Detection format (track IDs merged into detections)
gst-launch-1.0 v4l2src ! videoconvert ! video/x-raw,format=RGB \
  ! dctobdmodel-path=/path/to/model.synap \
  ! dctotrack output-format=detection output=text \
  ! videoconvert ! autovideosink
#include "apidctotrack.h"

// Initialize element
GstElement *pipeline = gst_pipeline_new("tracking-pipeline");
GstElement *dctotrack = api_dctotrack_init(pipeline, "tracker");

// Configure tracking parameters
api_dctotrack_set_track_thresh(dctotrack, 0.5);
api_dctotrack_set_high_thresh(dctotrack, 0.6);
api_dctotrack_set_match_thresh(dctotrack, 0.8);
api_dctotrack_set_track_buffer(dctotrack, 30);

// Configure output
api_dctotrack_set_output_mode(dctotrack, "mqtt");
api_dctotrack_set_output_format(dctotrack, "tracking");
api_dctotrack_set_mqtt_broker(dctotrack, "localhost");
api_dctotrack_set_mqtt_port(dctotrack, 1883);
api_dctotrack_set_mqtt_topic(dctotrack, "tracking/results");

// Enable statistics
api_dctotrack_set_track_statistics(dctotrack, true);

Performance Considerations​

  • Frame Rate: Set the frame-rate property to match your video source for accurate motion prediction
  • Track Buffer: Adjust track-buffer based on expected occlusion duration
  • Thresholds: Tune track-thresh, high-thresh, and match-thresh for your specific use case
  • Output Mode: Use none for maximum performance when tracking data is not needed downstream
