Properties

PropertyTypeDescriptionDefault

Property Details​

location​

Specifies the directory path where the MP4 video files need to be saved. This property is mandatory to be set before running the element in a pipeline.

  • Type: String
  • Default: NULL
  • Access: Read/Write

If /home/user/videos is the target location , then :

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord location=/home/user/videos ...
api_dctvrecord_set_location(<element_object>, "/home/user/videos");
g_object_set(<element_object>, "location", "/home/user/videos", NULL);
warning

The user must verify that the location value passed is an actual existing directory. If the directory doesn't exist, then dctvrecord will fail to start the recording operation.

prefix​

Specifies the prefix that needs to be prepended to the file names.

  • Type: String
  • Default: NULL
  • Access: Read/Write

If CAM1 is the prefix, then :

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord prefix=CAM1 ...
api_dctvrecord_set_prefix(<element_object>, "CAM1");
g_object_set(<element_object>, "prefix", "CAM1", NULL);

The files will be saved as follows:

  • With prefix: <PREFIX>_YYYY_MM_DD_HH_MM_SS_MSS.mp4
  • Without prefix: YYYY_MM_DD_HH_MM_SS_MSS.mp4

recording​

In MANUAL mode, writing true to this property will start recording, false will stop recording.

  • Type: Boolean
  • Default: false
  • Access: Read/Write (MANUAL mode), Read-only (AUTO mode)
note

This property is only valid in MANUAL mode. In AUTO mode, recording property has no role in controlling the video recording.

Usage:

  • Bash
  • With API
  • GST API
# Start recording (Manual mode)
gst-launch-1.0 ... ! dctvrecord mode=0 recording=true ...
// Start recording (Manual mode)
api_dctvrecord_set_recording(<element_object>, true);

// Stop recording
api_dctvrecord_set_recording(<element_object>, false);
// Start recording
g_object_set(<element_object>, "recording", true, NULL);

// Stop recording
g_object_set(<element_object>, "recording", false, NULL);

mode​

Specifies the recording mode. This plugin can record in 2 modes:

ModeDescription
Manual (0)User manually controls recording via API
Auto (1)Automatic recording based on MQTT object detection messages
  • Type: Integer [0/1]
  • Default: 0
  • Access: Read/Write

Usage:

  • Bash
  • With API
  • GST API
# Manual mode
gst-launch-1.0 ... ! dctvrecord mode=0 ...

# AUTO mode
gst-launch-1.0 ... ! dctvrecord mode=1 ...
// Manual mode
api_dctvrecord_set_mode(<element_object>, DCTVRECORD_MODE_MANUAL);

// AUTO mode
api_dctvrecord_set_mode(<element_object>, DCTVRECORD_MODE_AUTO);
// Manual mode
g_object_set(<element_object>, "mode", 0, NULL);

// AUTO mode
g_object_set(<element_object>, "mode", 1, NULL);

auto-enable​

Enables or disables the automatic recording feature in Auto mode. When enabled, the plugin connects to MQTT broker and starts monitoring for detection messages.

  • Type: Boolean
  • Default: true
  • Access: Read/Write
note

This property is only effective in Auto mode. Setting this to true initiates MQTT connection. Setting to false disconnects from MQTT and stops recording.

Usage:

  • Bash
  • With API
  • GST API
# Enable automatic recording
gst-launch-1.0 ... ! dctvrecord mode=1 auto-enable=true mqtt-topic=detections/camera1 ...
// Enable automatic recording
api_dctvrecord_set_auto_enable(<element_object>, true);

// Disable automatic recording
api_dctvrecord_set_auto_enable(<element_object>, false);
// Enable automatic recording
g_object_set(<element_object>, "auto-enable", true, NULL);

// Disable automatic recording
g_object_set(<element_object>, "auto-enable", false, NULL);
note

Before setting auto-enable property to true, ensure that the properties location, mqtt-topic and mode are set correctly.

host​

Specifies the MQTT broker host address to connect to in Auto mode.

  • Type: String
  • Default: "localhost"
  • Access: Read/Write
note

This property is protocol-agnostic and will be used for future TCP and Kafka support. Currently only MQTT is supported.

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord mode=1 host=192.168.1.100 port=1883 ...
api_dctvrecord_set_host(<element_object>, "192.168.1.100");
g_object_set(<element_object>, "host", "192.168.1.100", NULL);

port​

Specifies the MQTT broker port to connect to in Auto mode.

  • Type: Integer
  • Default: 1883
  • Range: 1-65535
  • Access: Read/Write
note

This property is protocol-agnostic and will be used for future TCP and Kafka support. Currently only MQTT is supported (default port: 1883).

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord mode=1 host=192.168.1.100 port=1883 ...
api_dctvrecord_set_port(<element_object>, 1883);
g_object_set(<element_object>, "port", 1883, NULL);

mqtt-topic​

Specifies the MQTT topic to subscribe for object detection messages in Auto mode. When detections are received on this topic, recording automatically starts. If auto-enable is true.

  • Type: String
  • Default: NULL
  • Access: Read/Write
note

This property is only effective in Auto mode. Setting this property when auto-enable is true will automatically connect to the broker.

If camera/detections is the topic name, then :

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord mode=1 host=192.168.1.100 port=1883 \
  auto-enable=true mqtt-topic=camera/detections ...
api_dctvrecord_set_mqtt_topic(<element_object>, "camera/detections" );
g_object_set(<element_object>, "mqtt-topic", "camera/detections", NULL);

MQTT Message Format (JSON):

The plugin expects JSON messages with the following structure:

{
  "timestamp": 1760334623.003448,
  "detections": [
    {"class": "person", "class_index":56, "confidence": 0.95, "bbox":{"x":0.703,"y":0.469,"width":0.292,"height":0.474}},
    {"class": "car", "class_index":56, "confidence": 0.95, "bbox":{"x":0.703,"y":0.469,"width":0.292,"height":0.474}}
  ]
}
  • When detections contain a class, Recording starts
  • When detections is empty, waits for det-timeout and then stops recording.
  • If no messages received for det-timeout seconds, recording stops

det-timeout​

Specifies the timeout period after which the recording is supposed to stop if no detections are present.

  • Type: Double (Floating point)
  • Default: 10.0
  • Range: > 0.0 seconds
  • Access: Read/Write
note

This property is effective only in Auto mode.

Usage:

  • Bash
  • With API
  • GST API
# Stop recording after 7 seconds of no detections
gst-launch-1.0 ... ! dctvrecord mode=1 det-timeout=7.0 ...
// Set detection timeout to 7 seconds
api_dctvrecord_set_det_timeout(<element_object>, 7.0);
// Set detection timeout to 7 seconds
g_object_set(<element_object>, "det-timeout", 7.0, NULL);

mqtt-client-id​

Specifies the client id with which the element is going to establish connection with the mqtt broker

  • Type: String
  • Default: <element-name>-<pid>
  • Access: Read/Write
note

This property is useful only in Auto mode.

Usage:

  • Bash
  • With API
  • GST API
gst-launch-1.0 ... ! dctvrecord mode=1 mqtt-client-id="newelement" ...
api_dctvrecord_set_mqtt_client_id(<element_object>, "newelement");
g_object_set(<element_object>, "det-timeout", "newelement", NULL);
note

Apart from the specified properties, this plugin also contains some extra properties that are related to the sink architecture in gstreamer. All of them are not tested.
