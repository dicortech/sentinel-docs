Adding a New Machine

This guide provides step-by-step instructions for adding a new machine layer implementation to the dctfcapture plugin. The machine layer handles platform-specific processing, such as hardware-accelerated JPEG encoding and color format conversion.

Overview​

The dctfcapture plugin uses a multi-layer architecture:

                      ┌─────────────────────────────────────┐
                      │         API Layer (C API)           │  - Public C interface
                      │      inc/api/ + src/api/            │  - Application-friendly functions
                      └─────────────────+───────────────────┘
                                        │
                      ┌─────────────────+───────────────────┐
                      │      GST Layer (GStreamer)          │  - GStreamer plugin interface
                      │      inc/gst/ + src/gst/            │  - Property management
                      └─────────────────+───────────────────┘  - Pipeline integration
                                        │
                  .---------------------+----------------------.
                  |                                            |
┌─────────────────+───────────────────┐    ┌───────────────────+─────────────────┐
│     COMM Layer (Communication)      │    │     MACH Layer (Processing)         │
│     inc/comm/ + src/comm/           │    │      inc/mach/ + src/mach/          │
└─────────────────────────────────────┘    └─────────────────────────────────────┘
       - Communication                            - Format conversion
       - MQTT                                     - JPEG encoding
                                                  - Platform-specific

The MACH layer is designed to be modular and swappable, allowing different implementations for:

  • Software implementation (MACH_GENERIC): Uses OpenCV for conversion
  • Hardware acceleration (MACH_HW, MACH_NVJPEG, etc.): Uses platform-specific APIs

Prerequisites​

Before adding a new machine layer, ensure you understand:

  1. Machine Layer Interface: All implementations must follow the interface defined in inc/mach/mach_generic.h
  2. GStreamer Video Formats: RGB, I420, UYVY support
  3. JPEG Encoding: Your platform's JPEG encoding API
  4. Build System: Meson build configuration

Step-by-Step Guide​

Step 1: Choose a Machine Name​

Pick a descriptive name for your machine implementation. Examples:

  • MACH_GENERIC - Software implementation (already exists)
  • MACH_HW - Generic hardware acceleration
  • MACH_NVJPEG - NVIDIA NVJPEG acceleration
  • MACH_VAAPI - Intel VAAPI acceleration
  • MACH_V4L2 - V4L2 hardware encoding

For this guide, we'll use MACH_HW as an example.

Step 2: Create Header File​

Create a new header file in inc/mach/ that follows the same interface as mach_generic.h.

File: inc/mach/mach_hw.h

#ifndef __MACH_HW_H__
#define __MACH_HW_H__

#ifdef MACH_HW

#include <gst/video/video.h>
#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

/**
 * @brief Machine layer context structure for fcapture (HW implementation)
 *
 * This is opaque to the GST layer. Add platform-specific handles here.
 */
typedef struct _MachFCaptureContext MachFCaptureContext;

/**
 * @brief Initialize machine layer context for fcapture
 *
 * @return MachFCaptureContext* Pointer to machine context, or NULL on failure
 */
MachFCaptureContext* machfcapture_init(void);

/**
 * @brief Cleanup machine layer context for fcapture
 *
 * @param ctx Machine context
 */
void machfcapture_cleanup(MachFCaptureContext *ctx);

/**
 * @brief Convert and save frame as JPEG using hardware acceleration
 *
 * This function handles:
 * - Format conversion (RGB/I420/UYVY to required format)
 * - Hardware-accelerated JPEG encoding
 * - File writing
 *
 * @param ctx Machine context
 * @param video_info GStreamer video info structure
 * @param buffer GStreamer buffer containing the frame
 * @param output_path Output file path for JPEG
 * @param quality JPEG quality (1-100)
 * @return bool true on success, false on failure
 */
bool machfcapture_convert_and_save_jpeg(
    MachFCaptureContext *ctx,
    GstVideoInfo *video_info,
    GstBuffer *buffer,
    const char *output_path,
    int quality
);

/**
 * @brief Get machine layer implementation name for fcapture
 *
 * @return const char* Implementation name (e.g., "Hardware-NVJPEG")
 */
const char* machfcapture_get_implementation_name(void);

/**
 * @brief Check if hardware acceleration is available for fcapture
 *
 * @return bool true if HW acceleration is used, false for software
 */
bool machfcapture_is_hw_accelerated(void);

#ifdef __cplusplus
}
#endif

#endif /* MACH_HW */

#endif /* __MACH_HW_H__ */

Key Points:

  • Keep the same function signatures as mach_generic.h
  • Wrap everything in #ifdef MACH_HW guards
  • The context structure can contain platform-specific handles internally

Implementation Guidelines:

  1. Error Handling: Use MACH_LOG_TAG for consistent logging
  2. Format Support: Handle RGB, I420, and UYVY formats

  5. Thread Safety: Consider if your HW API requires thread protection

Step 4: Update Machine Layer Header Selector​

Update inc/mach/mach_fcapture.h to include your new header.

File: inc/mach/mach_fcapture.h

#ifndef __MACH_FCAPTURE_H__
#define __MACH_FCAPTURE_H__

/**
 * @file mach_fcapture.h
 * @brief Machine layer abstraction for fcapture
 *
 * This header includes the appropriate machine-specific implementation
 * based on the MACH macro defined at build time.
 *
 * Supported MACH values:
 * - MACH_GENERIC: Generic software implementation using OpenCV (default)
 * - MACH_HW: Hardware-accelerated implementation
 */

/* Include machine-specific implementation based on MACH macro */
#if defined(MACH_GENERIC)
    #include "mach_generic.h"
#elif defined(MACH_HW)
    #include "mach_hw.h"
#else
    #error "No MACH type defined. Please define MACH_GENERIC or MACH_HW"
#endif

#endif /* __MACH_FCAPTURE_H__ */

Step 5: Update Meson Build Configuration​

Modify meson.build to support building with your new machine layer.

File: meson.build

# Machine layer selection option
valid_mach_options = [
  'MACH_GENERIC',
  'MACH_HW',        # Add your new option here
]  # Add new machine types here

And update the machine sources section:

# Plugin sources
mach_sources = [
  'src/mach/mach_generic.cpp',
  'src/mach/mach_hw.cpp',     # Add your new source file
] # Add new machine types' source here

Optional: Add platform-specific dependencies if needed:

# Get dependencies based on machine type
mach_option = get_option('mach')
mach_deps = []

if mach_option == 'MACH_HW'
  # Add hardware-specific dependencies
  # Example: NVJPEG
  # nvjpeg_dep = dependency('nvjpeg', required: true)
  # mach_deps += nvjpeg_dep

  # Or custom library paths
  # mach_deps += declare_dependency(
  #   link_args: ['-L/usr/local/cuda/lib64', '-lnvjpeg'],
  #   include_directories: include_directories('/usr/local/cuda/include')
  # )
endif

Then update the plugin library build section:

# Build the plugin as a shared library
gstdctfcapture = library(plugin_name,
  plugin_sources,
  include_directories : inc_dirs,
  cpp_args : plugin_cpp_args,
  dependencies : [gst_dep, gst_base_dep, gst_video_dep, opencv_dep] + mach_deps,  # Add mach_deps
  install : true,
  install_dir : get_option('libdir') / 'gstreamer-1.0',
)

Step 6: Update Meson Options (Optional)​

If you want to add specific build options for your machine layer, update meson_options.txt:

option('mach',
  type : 'string',
  value : 'MACH_GENERIC',
  description : 'Machine layer implementation (MACH_GENERIC, MACH_HW ...)')

# Optional: Add hardware-specific options
option('hw_encoder_path',
  type : 'string',
  value : '',
  description : 'Custom path to hardware encoder library')

Step 7: Build and Test​

Now build your new machine layer:

# Clean previous build
rm -rf builddir

# Configure with your new machine layer
meson setup builddir -Dmach=MACH_HW

# Compile
meson compile -C builddir

# Publish the executable and libraries to the target device.
# This will be machine/platform specific.

# In the target device, run self-test
GST_PLUGIN_PATH=builddir ./builddir/selftest

Step 8: Verify Integration​

Test your implementation with different scenarios:

1. Manual Mode Test​

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc num-buffers=1 ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture location=/tmp prefix=hw_test mode=0 capture=true ! \
  fakesink

2. Periodic Mode Test​

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=1 time-period=2 location=/tmp prefix=hw_periodic ! \
  fakesink

3. All Formats Test​

Test with RGB, I420, and UYVY formats to ensure your implementation handles all supported formats.

Common Pitfalls​

1. Format Conversion Issues​

  • Problem: Hardware encoders may not support all GStreamer formats directly
  • Solution: Implement format conversion in software before hardware encoding, or use hardware-accelerated converters if available

2. Memory Management​

  • Problem: Leaking hardware resources (GPU memory, encoder handles)
  • Solution: Ensure machfcapture_cleanup() frees ALL allocated resources

3. Threading​

  • Problem: Hardware APIs may not be thread-safe
  • Solution: Add mutex protection if needed, or ensure single-threaded access

4. Error Handling​

  • Problem: Silent failures make debugging difficult
  • Solution: Always use MACH_LOG_TAG for error messages and return false on failure

5. Build Dependencies​

  • Problem: Missing platform-specific libraries at build time
  • Solution: Document all required dependencies and update meson.build accordingly

Example Implementations​

Software Implementation (Reference)​

See src/mach/mach_generic.cpp for a complete software implementation using OpenCV.

Hardware Implementation Template​

The template provided in Step 3 serves as a starting point. Key areas to implement:

  1. Hardware Initialization (machfcapture_init)
  2. Frame Format Conversion (GStreamer → HW format)
  3. JPEG Encoding (using HW API)
  4. File Writing (save encoded JPEG)
  5. Cleanup (machfcapture_cleanup)

Debugging Tips​

  1. Enable Detailed Logging:

    GST_DEBUG=dctfcapture:5 GST_PLUGIN_PATH=builddir ./builddir/selftest

  2. Check Machine Layer Selection: During build, Meson should print:

    Message: Building with MACH_HW (machine implementation)

  3. Verify Function Calls: Add debug prints in your implementation to trace execution flow

  4. Test Incrementally:

    • Start with just initialization
    • Add format detection
    • Add encoding for one format
    • Add remaining formats
