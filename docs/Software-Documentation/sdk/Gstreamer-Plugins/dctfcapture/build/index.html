Build and Test

For building the Gstreamer plugins, we use the Meson build system as it is the one promoted by Gstreamer. The user can build 3 components. They are:

  1. Gstreamer plugin.
  2. Plugin API library.
  3. Test applications.
note

Make sure that the toolchain is setup, if you are building for the Astra platform.

Build with Meson​

Basic Build (Without MQTT)​

# Remove any build directory if already present:
rm -rf builddir/

# Setup build directory (default: MACH_GENERIC, comm=none)
meson setup builddir

# Compile
ninja -C builddir

Once the compilation is done, the following files among other should be generated in the builddir.

builddir/                   # Build directory
├── libapidctfcapture.a     # Plugin API library
├── libgstdctfcapture.so    # GStreamer plugin (plugin interface)
├── test_dctfcapture        # Test application for Gstreamer APIs
├── test_api_dctfcapture    # Test application for Custom APIs
└── selftest                # Self test application

Build with MQTT Support​

To enable MQTT communication framework and AUTO mode functionality:

# Setup build directory with MQTT support
meson setup builddir -Dcomm=mqtt

# Compile
ninja -C builddir

With MQTT enabled, additional files are generated:

builddir/                   # Build directory
├── libapidctfcapture.a     # Plugin API library
├── libgstdctfcapture.so    # GStreamer plugin (with MQTT support)
├── test_dctfcapture        # Test application for Gstreamer APIs
├── test_api_dctfcapture    # Test application for Custom APIs
├── mqtt_publisher          # MQTT publisher test utility
├── test_mqtt_auto_mode     # Test application for AUTO mode with MQTT
├── test_mode_change        # Test application for runtime mode switching
└── selftest                # Self test application

Build Options​

The plugin supports multiple build configuration options:

Machine Layer Selection​

Since this plugin is implemented in a layered architecture, support for additional machines can be added in mach/ layer of the plugin source. To build the plugin and library for a specific machine, issue the following command:

# Explicitly specify machine layer
meson setup builddir -Dmach=<machine-name>

Machine Layer Options:

  • MACH_GENERIC (default): Software implementation using OpenCV

You can find steps to add support for additional machine here.

Communication Framework Selection​

The communication framework determines whether MQTT support is included:

# Build without communication framework (default)
meson setup builddir -Dcomm=none

# Build with MQTT communication framework
meson setup builddir -Dcomm=mqtt

Communication Framework Options:

  • none (default): No communication framework, MQTT dependencies not required
  • mqtt: Enables MQTT communication layer for AUTO mode functionality

Combined Build Options​

You can combine multiple build options:

# Example: Machine-specific build with MQTT support
meson setup builddir -Dmach=MACH_GENERIC -Dcomm=mqtt

# Example: Reconfigure existing build to enable MQTT
meson configure builddir -Dcomm=mqtt
ninja -C builddir

Running the examples​

The examples can be run in 2 ways. It can be run in the platform where the plugin and its test code were compiled. Or else, if the compilation was done for a different target platform, then you will have to load the plugins and the examples to that target machine.

1. Run the example/test in the machine where it was compiled​

The plugins and the test code are output in the builddir directory. So provide the plugin path to Gstreamer before the test and the example pipeline are run.

# Pipeline
GST_PLUGIN_PATH=builddir gst-launch-1.0 ...

# Test app.
GST_PLUGIN_PATH=builddir ./builddir/<test-app>

2. Run the example/test in a target machine​

Upload the plugin and test app to the target platform. Here, we use the adb utility.

# Push the plugin to the plugin directory
adb push builddir/libgstobd.so <plugin directory> # Eg: /usr/lib/gstreamer-1.0/

# Push the test apps to the execution directory
adb push builddir/<test-app>

# Enter the adb shell and execute them
adb shell
shell# ./<test-app>
note

The examples shown here are run on the Host PC itself, where the compilation was done.

Usage Examples​

Manual Mode with Prefix​

The following example runs in Manual mode and captures 1 frame as the capture flag which is set true captures the first frame and will then be set to false state. Also, the file name will have a prefix appended to it.

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc num-buffers=10 ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=0 location=/tmp prefix=frame capture=true ! \
  fakesink

Output: /tmp/frame_2025_10_03_18_03_59_226.jpg

Manual Mode without Prefix​

The following example runs in Manual mode and captures 1 frame as the capture flag which is set true captures the first frame and will then be set to false state.

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc num-buffers=10 ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=0 location=/tmp capture=true ! \
  fakesink

Output: /tmp/2025_10_03_18_04_16_008.jpg

Periodic Mode​

The following example runs in Periodic mode and captures a frame every 3 seconds as the time-period is set to 3 seconds.

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=1 time-period=3 location=/tmp prefix=capture ! \
  videoconvert ! autovideosink

Captures every 3 seconds with timestamped filenames:

  • /tmp/capture_2025_10_03_18_03_59_226.jpg
  • /tmp/capture_2025_10_03_18_04_02_312.jpg
  • /tmp/capture_2025_10_03_18_04_05_401.jpg

AUTO Mode (MQTT-based Object Detection)​

note

AUTO mode requires the plugin to be built with MQTT support: meson setup builddir -Dcomm=mqtt

The following example runs in AUTO mode and captures frames when object detection messages arrive via MQTT:

# Start MQTT broker (in separate terminal)
mosquitto -v

# Run pipeline with AUTO mode
GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=2 mqtt-topic=object/detection \
  mqtt-host=localhost mqtt-port=1883 time-skip=100 \
  location=/tmp prefix=detected ! \
  videoconvert ! autovideosink
note

Requires a running MQTT broker (Mosquitto) and a publisher sending object detection messages to the configured topic.

MQTT Message Format (JSON):

{
  "objects_detected": true,
  "count": 2,
  "objects": [
    {"class": "person", "confidence": 0.95},
    {"class": "car", "confidence": 0.87}
  ]
}

Captures on object detection with timestamped filenames:

  • /tmp/detected_2025_10_09_14_30_45_123.jpg
  • /tmp/detected_2025_10_09_14_30_45_678.jpg

AUTO Mode with Remote Broker​

Connect to a remote MQTT broker:

GST_PLUGIN_PATH=builddir gst-launch-1.0 videotestsrc ! \
  video/x-raw,format=I420,width=640,height=480 ! \
  dctfcapture mode=2 mqtt-topic=camera/detection \
  mqtt-host=192.168.1.100 mqtt-port=1883 time-skip=0 \
  location=/tmp prefix=remote ! \
  videoconvert ! autovideosink

Test Applications​

1. Self-Test (Automated Comprehensive Tests)​

Automated test suite that validates all plugin functionality:

GST_PLUGIN_PATH=builddir ./builddir/selftest

Test Coverage:

  • Manual mode capture with prefix
  • Manual mode capture without prefix
  • Periodic mode capture (time-based intervals)
  • API getter functions
  • Runtime property modification

Exit code 0 indicates all tests passed.

2. GStreamer-based Test (test_dctfcapture)​

Interactive test using direct GStreamer API:

GST_PLUGIN_PATH=builddir ./builddir/test_dctfcapture

3. API-based Test (test_api_dctfcapture)​

Interactive test using the simplified C API:

GST_PLUGIN_PATH=builddir ./builddir/test_api_dctfcapture

The interactive tests provide prompts to:

  1. Select capture mode (Manual/Periodic)
  2. Set time period (for Periodic mode)
  3. Automatically test the selected configuration

4. MQTT AUTO Mode Test (test_mqtt_auto_mode)​

note

Requires build with MQTT support: meson setup builddir -Dcomm=mqtt

Test AUTO mode with MQTT object detection:

# Start MQTT broker first
mosquitto -v

# Run AUTO mode test (captures for 10 seconds)
GST_PLUGIN_PATH=builddir ./builddir/test_mqtt_auto_mode 10

What it tests:

  • MQTT connection to broker (localhost:1883)
  • Subscription to "object/detection" topic
  • Frame capture on object detection messages
  • Throttling with time-skip configuration
  • Auto-reconnection on broker restart

Usage:

./builddir/test_mqtt_auto_mode <duration_seconds>

5. Mode Change Test (test_mode_change)​

note

Requires build with MQTT support: meson setup builddir -Dcomm=mqtt

Test runtime mode switching and MQTT connection management:

# Start MQTT broker first
mosquitto -v

# Run mode change test
GST_PLUGIN_PATH=builddir ./builddir/test_mode_change

What it tests:

  • MANUAL → AUTO mode switching (MQTT connects)
  • AUTO → PERIODIC mode switching (MQTT disconnects)
  • PERIODIC → AUTO mode switching (MQTT reconnects)
  • Resource cleanup during mode transitions
  • Runtime property reconfiguration

Dependencies​

Core Dependencies (Always Required)​

  • GStreamer >= 1.0
  • GStreamer Base >= 1.0
  • GStreamer Video >= 1.0
  • OpenCV 4 (for MACH_GENERIC)
  • Meson >= 0.54

Install on Ubuntu/Debian:

sudo apt-get install libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
                     libopencv-dev meson ninja-build

MQTT Communication Dependencies (Optional)​

Only required when building with -Dcomm=mqtt option:

  • Mosquitto MQTT client library (libmosquitto-dev)
  • Mosquitto broker (for testing)

Install on Ubuntu/Debian:

sudo apt-get install libmosquitto-dev mosquitto mosquitto-clients
note

MQTT dependencies are only required if you build with -Dcomm=mqtt to enable AUTO mode (mode=2) for event-driven capture. If you don't need MQTT functionality, you can build without these dependencies using the default build configuration.
